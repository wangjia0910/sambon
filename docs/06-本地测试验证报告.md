## 5. 缺陷与处置

### 5.1 D-01（**真实缺陷，已修复并回归**）成果正文证件号脱敏残留

| 项 | 内容 |
|---|---|
| 现象 | `sanitizeSubmissionText()` 先执行手机号正则 `1[3-9]\d{9}`，18 位证件号 `110101199001011234` 中间 11 位 `19900101123` 被误判为手机号并替换，输出 `110101[已脱敏]4`；证件号正则随后无法匹配，**地区码与末位残留** |
| 影响 | 完整证件号未落库，但残留片段，属 CONTRACT §10.2「不得存储明文 PII」口径下的脱敏不彻底；研发自检 ⑲ 只校验手机号与 `[已脱敏]` 标记，**未覆盖证件号残留**，因此未发现 |
| 发现方式 | 独立验证 V-14 打印 `result_preview` 时暴露；随后补 `!/\d{6,}/` 强断言固化 |
| 修复 | `src/domain.mjs` `sanitizeSubmissionText()`：**证件号正则优先**，且两条正则均加数字边界 `(?<!\d)` / `(?!\d)`，避免长数字串被部分匹配。修复后输出 `联系电话 [已脱敏]，证件号 [已脱敏]` |
| 回归 | 语法 5/5；`tests/smoke.mjs` **20/20**；`tests/verify-local.mjs` **32/32**（连跑 2 次）；V-14 断言 `无长数字残留=true` |
| 后续建议 | **P1**：把该证件号边界用例补入研发自检（本轮未改 `tests/smoke.mjs`，以保持阶段 C 定稿的 20 项断言口径稳定）；正式上线前将正则方案替换为更完整的 PII 识别 + 日志扫描 |

### 5.2 验证脚本自身口径错误（**非实现缺陷**，逐条修正）

| # | 现象 | 归因 | 处置 |
|---|---|---|---|
| 1 | A 组执行中断，连带 V-03 / V-04 未执行、`initial_total=undefined`、V-32 失败 | 对 `GET` 请求传了 body，`fetch` 抛 `Request with GET/HEAD method cannot have body` | `call()` 按方法判断是否带 body |
| 2 | V-07 失败 | `timeoutCreditPenalty()` 返回对象 `{credit_delta:-5}`，而非标量 | 改断言为 `.credit_delta === -5` |
| 3 | V-14 字段 undefined | 视图字段名为 `result_preview` / `result_pii_redacted`，非 `result.text` | 改用实际字段，并改查 `TaskSubmitted` 事件 payload |
| 4 | V-18 失败 | 事件快照在**结算前**取得，缺少 `TaskVerified / CreditTransferred / SettlementCompleted` | 结算后重新取回放快照 |
| 5 | V-25 失败 | `escrow` 是**全局累计科目**（含其他未结任务），且争议响应顶层无 `model_decision` 字段 | 改用「争议前后增量 = 0 + 该任务正向流水 0 笔」，模型证据改查 `DisputeOpened` 事件与 `llm_summary.decision` |
| 6 | V-32 失败 | 由 #1 导致 `metrics.initial_total` 未初始化 | 随 #1 修复 |
| 7 | V-04 失败（权重数值打印却完全正确） | 基准键名大小写不符：实现为 `P_accept / R_risk / quality`，脚本写成 `p_accept / risk / description_quality` | 按契约符号修正基准，并增加键数量相等校验 |
| 8 | V-25 二次失败 | 同上，响应顶层无 `model_decision` | 同 #5 |

> 说明：首轮独立验证 `PASS 25 / FAIL 6`、第二轮 `PASS 30 / FAIL 2`，均为上述口径问题；期间**未发现除 D-01 外的实现缺陷**。验证脚本修订后 `PASS 32 / FAIL 0`，退出码 0。

## 7. 已知限制 / 不构成上线结论

- **存储**：内存仓储，进程重启数据归零；无持久化、无数据库、无真实时钟与定时任务。
- **外部能力**：不接真实大模型（LLM 适配层恒 `degraded:true` 规则兜底）、不接真实支付、不接公链（仅本地 Merkle 摘要）、不接消息通道。
- **合规**：个性化关闭开关为**进程级全局单例**（账号级按 `user_id` 隔离列 P1）；未成年人限制与举报入口仅钩子占位；算法备案与区块链信息服务备案未完成。
- **工程**：未做安全测试、压测与灾备演练、灰度与回滚演练；本报告的耗时数据**不是**生产性能结论。
- **闸门**：V1–V8 上线闸门状态为「未上线、不触发」，不得表述为已通过（`CONTRACT.md` v0.2 §11 / `docs/07`）。法务维持「有条件通过、未触发一票否决」，本报告不构成法律意见。
