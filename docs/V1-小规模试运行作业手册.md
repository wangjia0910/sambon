## 2. 试运行准入（"小规模"如何落地）

"小规模"不靠临时改代码（无 PAT 推不动、也不该为试运行动核心注册逻辑），靠**运营级三重约束**：

### 2.1 名单制准入（不公开分发）

- 只把访问入口发给**书面确认过的受邀测试者**，不做公开传播、不做 SEO 引流、不投广告。
- 受邀测试者在 `ops/pilot-roster.md`（不入库）登记：邮箱、角色、邀请日期、测试目的。
- 建议初始规模：**发布方 ≤ 5、接单方 ≤ 20、并发任务 ≤ 10**。达到上限即停发邀请，不扩量。
- 账号由受邀者自助注册（现有 `hRegister` 已要求非一次性邮箱、密码 10–128 位、GPC 自动关个性化）；`ADMIN_BOOTSTRAP_TOKEN` 仅在初始化运维账号时使用，用完即移除。

### 2.2 资金护栏（低赏金 + 人工兜底）

- 试运行期 **SBC 初始额度按现有配置（默认 1000，可用 `INITIAL_SBC` 环境变量下调）**，不接任何真实法币（红线 §10.1）。
- 发布任务时**人工约定单任务赏金上限**，建议 ≤ 100 SBC；超出则由运营驳回。服务费率 5% 按现有 `SERVICE_FEE_RATE` 不变。
- **每一笔结算、争议裁定、账号处罚必须人工在运营台确认**（现有 `hVerify` / `hDispute` 人工闸门 + `jobs.js` 只出工单不自动结算，红线 §10.3）。
- SBC 不可兑付、不可转让、不可交易、无收益承诺（红线 §10.1）；对外文案不得出现"提现/兑换/变现/收益"字样。

### 2.3 数据与内容护栏

- 任务正文继续走 `sanitizeSubmissionText()` 脱敏（证件号正则优先 + 长数字兜底），**不得录入真实手机号/身份证/精确定位**（红线 §10.2）。
- 测试任务一律用虚构样例（红线 §10.7）；测试者若误填真实 PII，运营须立即编辑脱敏并记入 `ops/pilot-incidents.md`。
- 未成年人 18+ 限制、违禁任务预检、举报入口照常生效（红线 §10.5）；**不开放真实年龄核验供应商**（E-11 后置）。

## 3. 试运行期不可放宽的六条（CONTRACT §10）

| # | 红线       | 试运行期要求                                 |
| - | -------- | -------------------------------------- |
| 1 | SBC 非资产  | 不接法币、不兑付、不转让、不交易、无收益承诺；8 条资产化端点保持 404  |
| 2 | 零真实 PII  | 不存明文手机号/身份证/精确定位；联系方式虚拟号；日志脱敏          |
| 3 | 人工兜底     | 结算/争议/处罚必须人工确认；`model_decision` 恒 null |
| 4 | 个性化可关    | 账号级"关闭个性化"开关有效，关闭后服务端强制中性排序            |
| 5 | 限制与治理    | 18+ 限制、违禁预检、举报入口可用                     |
| 6 | 零 PII 上链 | 仅本地 Merkle 摘要，零 PII、零任务正文上链            |

> 这六条**不是监管要求，是产品自己的设计不变量**。试运行不"先不管"这些——它们恰好是试运行期防止真实伤害的护栏。

## 4. C-01 结算双花：已从数据库层修复

**状态（2026-11-20，CONTRACT D-16）**：C-01 **已修复**，不再是试运行的遗留风险。

**修复内容**：
- `settlement_guards(task_id PRIMARY KEY)` + `INSERT OR IGNORE` 原子守卫：并发结算只有一个能占位，其余返回 409 `SETTLEMENT_CONFLICT`；
- 覆盖三条资金终局路径：`hVerify` 验收、`hDispute(resolve=pay_solver)` 裁定结算、`refund_publisher/close` 退款关闭，天然互斥；
- 失败可重试：batch 未提交时释放守卫，不永久锁死；
- 并发回归 `tests/verify-settlement-concurrency.mjs` 12 项全绿，负向注入（去掉守卫）复现原始 bug 证明测试有效；门禁新增代码能力项 **C-17**（现 17/17）。

**试运行期仍建议保留的纵深防御**（与修复无关，是运营纪律）：
1. **同一任务只由一名运营确认结算**：验收与争议裁定不由同一人并发操作；结算前在运营台刷新确认任务状态。
2. **每日对账**：每天收工前跑账本守恒校验（`ledger_entries` 双腿平衡 + 哈希链校验），发现差异立即冻结该任务并记入 `ops/pilot-incidents.md`。
3. **低赏金上限**：≤100 SBC 限制单次资金暴露面。

> 详见 `docs/project/07-代码审计报告.md` v1.2 §2.1 / §6。

## 5. 监控指标与观察窗口

| 指标     | 观察方式                      | 试运行关注阈值（非 G1–G7 正式指标）           |
| ------ | ------------------------- | ------------------------------- |
| 结算偏差   | 每日账本守恒 + 哈希链校验            | 差异 ≠ 0 立即冻结                     |
| 任务闭环   | 运营台任务状态分布                 | 卡在 `PENDING_REVIEW` > 24h 需人工介入 |
| 争议率    | 争议任务 / 已结算任务              | 明显偏高（如 > 10%）记录并复盘              |
| PII 泄漏 | 抽查任务正文 + 事件 payload       | 发现真实 PII 立即脱敏并记事件               |
| 红线越界   | `/api/config` 红线端点 404 抽检 | 任一资产化端点可用 = 立即停服                |
| 人工闸门   | 审计日志 `audit_log`          | 无人工确认的结算记录 = 停服排查               |

**观察窗口**：建议先跑 **7 天**（不等同 G1–G7 的 14 天灰度），窗口内每天记一份 `ops/pilot-daily.md`（不入库）。

## 6. 退出与回滚条件

**立即暂停试运行**（停发邀请、冻结写操作、保留读）的触发条件：

- 账本差异 ≠ 0 且无法当日定位；
- 出现真实 PII 上链或明文存储；
- 任一 SBC 资产化端点可用，或出现法币兑付表述；
- 出现无人工确认的自动结算；
- 出现未成年人注册或重大违禁任务漏检。

**回滚**：V1 试运行不改生产代码、不改 D1 schema，回滚 = 停止分发入口 + 移除受邀账号 + 保留数据备查；无需版本回退。如需彻底清空，用 D1 Time Travel 恢复到试运行前时间点（演练前先在演练库验证，勿直接动生产）。

## 7. 对外口径（红线表述）

**允许说**：

- "三宝殿 V1 小规模受控试运行 / 内部测试阶段"
- "面向受邀测试者开放，功能与账本为真实系统，仅限平台内贡献积分 SBC"

**禁止说**：

- "已正式上线 / 已开放注册 / 平台已上线运营"
- "已通过合规审查 / 网信办认证 / 已备案"（法条 18 项未核销，E-20 未签发）
- SBC 可"提现 / 兑换 / 交易 / 变现 / 产生收益"

**口径落地**：当前线上页面仍标"演示环境 / 不构成正式运营许可"。**V1 试运行期间保留这一保守表述不动**——把姿态切换为"受控试运行"只体现在内部运营手册与对受邀者的说明中，不对外宣称正式上线。改页面文案需要重新部署（当前无 PAT），且改了反而需要更谨慎的合规措辞，故本轮不动。
