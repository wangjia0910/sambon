## 2. 一期运营护栏

一期面向公众开放，靠三重护栏保证资金与数据安全：

### 2.1 开放注册与账号治理

- 一期**面向公众开放注册**（`hRegister`：非一次性邮箱、密码 10–128 位、GPC 自动关个性化）。
- `ADMIN_BOOTSTRAP_TOKEN` 仅用于初始化运维管理员账号，用完即移除；`admin` 角色只能经引导端点创建，不接受自助注册。
- 二期再评估 G1–G7 规模灰度（单一海外区域、≥500 接单人、14 天）。

### 2.2 资金护栏（低赏金 + 人工兜底）

- **SBC 初始额度按现有配置（默认 1000，可用 `INITIAL_SBC` 环境变量调整）**，不接任何真实法币（红线 §10.1）。
- 服务费率 5% 按现有 `SERVICE_FEE_RATE` 不变；发布即冻结赏金 + 服务费，结算经人工确认后转付。
- **每一笔结算、争议裁定、账号处罚必须人工在运营台确认**（现有 `hVerify` / `hDispute` 人工闸门 + `jobs.js` 只出工单不自动结算，红线 §10.3）。
- SBC 不可兑付、不可转让、不可交易、无收益承诺（红线 §10.1）；对外文案不得出现"提现/兑换/变现/收益"字样。

### 2.3 数据与内容护栏

- 任务正文继续走 `sanitizeSubmissionText()` 脱敏（证件号正则优先 + 长数字兜底），**不得录入真实手机号/身份证/精确定位**（红线 §10.2）。
- 测试任务一律用虚构样例（红线 §10.7）；测试者若误填真实 PII，运营须立即编辑脱敏并记入 `ops/pilot-incidents.md`。
- 未成年人 18+ 限制、违禁任务预检、举报入口照常生效（红线 §10.5）；**不开放真实年龄核验供应商**（E-11 后置）。

## 4. C-01 结算双花：已从数据库层修复

**状态（2026-11-20，CONTRACT D-16）**：C-01 **已修复**，不是一期风险。

**修复内容**：
- `settlement_guards(task_id PRIMARY KEY)` + `INSERT OR IGNORE` 原子守卫：并发结算只有一个能占位，其余返回 409 `SETTLEMENT_CONFLICT`；
- 覆盖三条资金终局路径：`hVerify` 验收、`hDispute(resolve=pay_solver)` 裁定结算、`refund_publisher/close` 退款关闭，天然互斥；
- 失败可重试：batch 未提交时释放守卫，不永久锁死；
- 并发回归 `tests/verify-settlement-concurrency.mjs` 12 项全绿，负向注入（去掉守卫）复现原始 bug 证明测试有效；门禁新增代码能力项 **C-17**（现 17/17）。

**一期保留的纵深防御**（与修复无关，是运营纪律）：
1. **同一任务只由一名运营确认结算**：验收与争议裁定不由同一人并发操作；结算前在运营台刷新确认任务状态。
2. **每日对账**：每天收工前跑账本守恒校验（`ledger_entries` 双腿平衡 + 哈希链校验），发现差异立即冻结该任务并记入 `ops/pilot-incidents.md`。
3. **异常监控**：单任务结算后出现额外账本腿立即冻结排查。

> 详见 `docs/project/07-代码审计报告.md` v1.2 §2.1 / §6。

## 5. 监控指标与观察窗口

| 指标     | 观察方式                      | 一期关注阈值（G1–G7 数值闸门在二期）           |
| ------ | ------------------------- | ------------------------------- |
| 结算偏差   | 每日账本守恒 + 哈希链校验            | 差异 ≠ 0 立即冻结                     |
| 任务闭环   | 运营台任务状态分布                 | 卡在 `PENDING_REVIEW` > 24h 需人工介入 |
| 争议率    | 争议任务 / 已结算任务              | 明显偏高（如 > 10%）记录并复盘              |
| PII 泄漏 | 抽查任务正文 + 事件 payload       | 发现真实 PII 立即脱敏并记事件               |
| 红线越界   | `/api/config` 红线端点 404 抽检 | 任一资产化端点可用 = 立即停服                |
| 人工闸门   | 审计日志 `audit_log`          | 无人工确认的结算记录 = 停服排查               |

**观察节奏**：一期每日记一份运营日志（可存 `ops/` 不入库）；G1–G7 的 14 天灰度数值闸门在二期执行。

## 6. 退出与回滚条件

**立即暂停一期服务**（冻结写操作、保留读）的触发条件：

- 账本差异 ≠ 0 且无法当日定位；
- 出现真实 PII 上链或明文存储；
- 任一 SBC 资产化端点可用，或出现法币兑付表述；
- 出现无人工确认的自动结算；
- 出现未成年人注册或重大违禁任务漏检。

**回滚**：一期不改生产代码结构，回滚 = 通过 Cloudflare Pages 重新部署上一版本 + 保留数据备查。如需彻底清空，用 D1 Time Travel 恢复到上线前时间点（演练前先在演练库验证，勿直接动生产）。
