## 一、环境准备

### 1.1 开发机

| 依赖 | 版本 | 说明 |
|---|---|---|
| Node.js | 18+（推荐 20/22） | 本地开发、测试、构建 |
| Git | 任意 | 版本管理 |
| curl | 任意 | 接口调试（可选） |

**无需 `npm install`**——项目零第三方依赖，只用 Node 内置模块。

### 1.2 生产环境

| 资源 | 说明 |
|---|---|
| Cloudflare 账号 | 已接入 `sambon.net` |
| Pages 项目 | 已 `Connect to Git` |
| D1 数据库 | 名为 `sanbaodian-db`（或自定义） |
| Wrangler（可选） | 本地 `wrangler pages dev` 或 D1 迁移 |

### 1.3 克隆仓库

```bash
git clone https://github.com/wangjia0910/sambon.git
cd sambon
node --version      # 确认 ≥ 18
```

## 二、本地开发与联调

### 2.1 三种运行模式

| 命令 | 端口 | 用途 | 数据 |
|---|---|---|---|
| `npm run preview` | 8788 | **推荐**：真实 `dispatch()` + 内存 D1，前后端行为与生产一致 | 内存，重启清空 |
| `npm start` | 8787 | L0 纯内存原型，快速验证领域规则 | 内存，重启清空 |
| 直接打开 `cloudflare/index.html` | — | L0 静态演示台，浏览器内 mock，不发真实请求 | 无 |

日常开发用 `npm run preview`：

```bash
npm run preview
# → http://127.0.0.1:8788
```

预置环境：
- `ADMIN_BOOTSTRAP_TOKEN=preview-admin`
- `INITIAL_SBC=1000`
- `RATE_LIMIT_DISABLED=true`（便于压测）
- `COOKIE_SECURE=false`（http 下可带 Cookie）

### 2.2 修改代码后的重建

生产前端与后端副本由构建脚本生成，改完源文件必须重建：

```bash
npm run build
```

构建会：
1. 重建 `cloudflare/`（静态产物）；
2. 同步 `src/domain.mjs` → `prod/lib/domain.js`、`cloudflare/src/domain.mjs`；
3. 从 `prod/lib/schema.js` 导出 `schema.sql`。

> 直接改 `cloudflare/` 或 `prod/lib/domain.js` 会在下次构建时被覆盖。

### 2.3 目录职责速查

| 想改什么 | 改哪里 |
|---|---|
| 状态机、积分规则、推送打分 | `src/domain.mjs` |
| 接口编排、账本、人工闸门 | `prod/lib/api.js` |
| 表结构 / 新增字段 | `prod/lib/schema.js` |
| 用户版页面（大厅/榜单/发布） | `prod/site/member.js` + `member.html` + `member.css` |
| 运营台页面 | `prod/site/app.js` + `index.html` + `styles.css` |
| SEO / 站点地图 / 抓取规则 | `prod/site/seo.js`、`sitemap.xml`、`robots.txt` |
| 响应头 / 路由重写 | `tools/build-cloudflare.mjs`（`_headers` / `_redirects`） |

## 三、部署到 Cloudflare

### 3.1 接入方式

仓库已通过 **Connect to Git** 与 Cloudflare Pages 关联，`main` 分支每次 push 自动构建部署。

Pages 构建配置：

| 项 | 值 |
|---|---|
| 构建命令 | 留空（或 `npm run build`） |
| 输出目录 | `cloudflare` |
| 根目录 | `/` |

### 3.2 部署步骤

```bash
# 1. 本地先验证
npm run build
npm test

# 2. 推送触发自动部署
git add -A
git commit -m "feat: 你的改动"
git push origin main
```

### 3.3 路由规则

| 路径 | 指向 | 说明 |
|---|---|---|
| `/`、`/app` | `member.html` | 用户版主入口 |
| `/product`、`/production` | `prod.html` | 运营台（建议在 robots.txt 屏蔽） |
| `/demo`、`/index.html` | `index.html` | L0 演示台 |
| `/api/*` | Pages Functions | 由 `_routes.json` 限定 |
| 其他 | 静态资源 | 走静态通道，不消耗 Functions 配额 |

### 3.4 绑定 D1（必须，一次性）

控制台 → Pages 项目 → **Settings → Functions → D1 database bindings**：

```
Variable name: DB
D1 database:   sanbaodian-db
```

> **变量名必须是 `DB`**（代码按 `env.DB` 读取）。名字不对等同未绑定 → 站点进入 `mode=demo`，写操作 503。

初始化表结构（首次或表结构变更后）：

```bash
npx wrangler d1 execute sanbaodian-db --file=schema.sql --remote
```

表结构使用 `CREATE TABLE IF NOT EXISTS`，重复执行安全；新增列通过幂等补列语句处理。

### 3.5 部署后核验

```bash
curl -s https://sambon.net/api/health
```

关键字段：

| 字段 | 期望 | 含义 |
|---|---|---|
| `mode` | `production` | D1 已绑定 |
| `db` | `d1` | 存储为 D1 |
| `status` | `healthy` | 自检通过 |
| `admin_bootstrap_available` | 初始 `true`，建管理员后 `false` | 引导端点状态 |
| `components.llm.mode` | `rule` 或 `llm` | 大模型是否启用 |
| `components.cron.enabled` | 是否配置 `CRON_SECRET` | 定时作业可用性 |

## 四、初始化与配置

### 4.1 创建首个管理员

1. Pages 项目 → Settings → Environment variables，添加：

```
ADMIN_BOOTSTRAP_TOKEN = <随机强字符串，如 openssl rand -hex 24 的结果>
```

2. 重新部署使其生效，然后调用：

```bash
curl -X POST https://sambon.net/api/admin/bootstrap \
  -H 'Content-Type: application/json' \
  -d '{
    "bootstrap_token": "<刚设置的令牌>",
    "email": "admin@yourdomain.com",
    "password": "<≥12 位强口令>",
    "display_name": "平台管理员"
  }'
```

成功返回 `201`，含 `user_id`。

3. **立即移除** `ADMIN_BOOTSTRAP_TOKEN` 环境变量并重新部署。之后该端点返回 `503 ADMIN_BOOTSTRAP_DISABLED`（已存在管理员时返回 `409 ADMIN_EXISTS`）。

### 4.2 环境变量清单

在 Pages 项目 **Settings → Environment variables** 配置。密钥类用 "Encrypt" 保存。

| 变量 | 默认 | 作用 |
|---|---|---|
| `INITIAL_SBC` | `1000` | 新账号初始 SBC |
| `PBKDF2_ITERATIONS` | `120000` | 口令派生轮数，不建议下调 |
| `EMAIL_VERIFICATION_REQUIRED` | 不强制 | `true` 时未验证账号不能发布/接单 |
| `ENFORCE_STRONG_PASSWORD` | 不强制 | `true` 时要求 ≥12 位 + 3 类字符 |
| `LLM_API_URL` | 空 | OpenAI 兼容 chat/completions 端点 |
| `LLM_API_KEY` | 空 | 模型密钥（密文） |
| `LLM_MODEL` | `gpt-4o-mini` | 模型名 |
| `NOTIFY_WEBHOOK_URL` | 空 | 通知 Webhook；不配则 `queue_only` |
| `NOTIFY_WEBHOOK_SECRET` | 空 | Webhook HMAC 签名密钥（密文） |
| `CRON_SECRET` | 空 | `/api/admin/cron` 的 `X-Cron-Secret` |
| `COOKIE_SECURE` | 强制 | 仅本地 http 联调可设 `false` |
| `RATE_LIMIT_DISABLED` | 空 | 仅本地回归，生产必须留空 |
| `EMAIL_VERIFICATION_DEV_ECHO` | 空 | **仅本地**，生产严禁设置 |

### 4.3 未配置项的行为

- 未配 `LLM_*`：推送打分走规则引擎，`algorithm_degraded=true`，功能不受影响。
- 未配 `NOTIFY_*`：通知落库并标记 `queue_only`（`sent=0`），不伪造已发送。
- 未配 `CRON_SECRET`：`/api/admin/cron` 返回 `503 CRON_DISABLED`（不留后门）。
- 未配 `ADMIN_BOOTSTRAP_TOKEN`：引导端点 503，已有管理员可正常登录。

## 五、完整业务闭环演示（curl）

以下演示「发布 → 审核 → 推送 → 接单 → 提交 → 验收 → 结算」全流程。以本地 `http://127.0.0.1:8788` 为例，生产环境替换域名即可。

### 5.0 准备

```bash
BASE=http://127.0.0.1:8788
JAR_PUB=/tmp/pub.cookies     # 发布方 cookie
JAR_SOL=/tmp/sol.cookies     # 接单人 cookie
JAR_ADM=/tmp/adm.cookies     # 管理员 cookie
```

> 每个账号一个 cookie jar，curl 用 `-c` 写、`-b` 读。CSRF 令牌从登录/注册响应里取。

### 5.1 注册三方账号

```bash
# 管理员（仅本地；生产用 bootstrap 端点）
curl -s -X POST "$BASE/api/admin/bootstrap" -H 'Content-Type: application/json' \
  -d '{"bootstrap_token":"preview-admin","email":"admin@example.com","password":"AdminPassw0rd!","display_name":"管理员"}'

# 发布方
curl -s -c $JAR_PUB -X POST "$BASE/api/auth/register" -H 'Content-Type: application/json' \
  -d '{"email":"pub1@example.com","password":"Passw0rd!2026","role":"publisher","display_name":"发布方甲"}' \
  | tee /tmp/pub.reg.json

# 接单人
curl -s -c $JAR_SOL -X POST "$BASE/api/auth/register" -H 'Content-Type: application/json' \
  -d '{"email":"solver1@example.com","password":"Passw0rd!2026","role":"solver","display_name":"猎人乙"}' \
  | tee /tmp/sol.reg.json
```

注册返回 `data.session.csrf_token`，取出：

```bash
CSRF_PUB=$(python -c "import json;print(json.load(open('/tmp/pub.reg.json'))['data']['session']['csrf_token'])")
CSRF_SOL=$(python -c "import json;print(json.load(open('/tmp/sol.reg.json'))['data']['session']['csrf_token'])")
```

### 5.2 发布任务（发布方）

必填：`title`、`description`、`category`、`bounty`、`acceptance_criteria`；可选 `deadline_hours`（1–720，默认 48）。

```bash
curl -s -b $JAR_PUB -X POST "$BASE/api/tasks" \
  -H 'Content-Type: application/json' \
  -H "X-CSRF-Token: $CSRF_PUB" \
  -d '{
    "event_id": "evt-pub-001",
    "title": "整理一份社区旧物回收点清单",
    "description": "收集本社区 3 公里内 10 个旧物回收点的地址与营业时间。",
    "category": "信息整理",
    "bounty": 100,
    "acceptance_criteria": "清单含地址、营业时间、是否接收大件，附地图标注。",
    "deadline_hours": 72
  }' | tee /tmp/task.json
```

返回任务 `task_id` 与 `state=PENDING_REVIEW`。发布时冻结 `bounty + 5% 服务费 = 105 SBC`。

```bash
TASK_ID=$(python -c "import json;print(json.load(open('/tmp/task.json'))['data']['task_id'])")
```

### 5.3 审核与推送（管理员）

```bash
# 登录管理员
curl -s -c $JAR_ADM -X POST "$BASE/api/auth/login" -H 'Content-Type: application/json' \
  -d '{"email":"admin@example.com","password":"AdminPassw0rd!"}' | tee /tmp/adm.login.json
CSRF_ADM=$(python -c "import json;print(json.load(open('/tmp/adm.login.json'))['data']['session']['csrf_token'])")

# 审核通过
curl -s -b $JAR_ADM -X POST "$BASE/api/tasks/$TASK_ID/review" \
  -H 'Content-Type: application/json' -H "X-CSRF-Token: $CSRF_ADM" \
  -d '{"event_id":"evt-adm-001","decision":"approve"}'

# 推送给候选人
curl -s -b $JAR_ADM -X POST "$BASE/api/tasks/$TASK_ID/dispatch" \
  -H 'Content-Type: application/json' -H "X-CSRF-Token: $CSRF_ADM" \
  -d '{"event_id":"evt-adm-002","top_k":5,"channel":"in_app"}'
```

`dispatch` 返回本批次候选与各自分数（含 `weight_version`）。

### 5.4 接单与提交（接单人）

```bash
# 接单
curl -s -b $JAR_SOL -X POST "$BASE/api/tasks/$TASK_ID/accept" \
  -H 'Content-Type: application/json' -H "X-CSRF-Token: $CSRF_SOL" \
  -d '{"event_id":"evt-sol-001"}'

# 提交成果（正文自动 PII 脱敏）
curl -s -b $JAR_SOL -X POST "$BASE/api/tasks/$TASK_ID/submit" \
  -H 'Content-Type: application/json' -H "X-CSRF-Token: $CSRF_SOL" \
  -d '{"event_id":"evt-sol-002","content":"清单已完成，共 10 个回收点，详见附件说明。联系电话 13800000000。"}'
```

返回中 `content` 的手机号会被替换为 `[已脱敏]`。

### 5.5 验收与结算（发布方本人）

```bash
curl -s -b $JAR_PUB -X POST "$BASE/api/tasks/$TASK_ID/verify" \
  -H 'Content-Type: application/json' -H "X-CSRF-Token: $CSRF_PUB" \
  -d '{"event_id":"evt-pub-002","decision":"approve","rating":5}'
```

结算效果：
- 接单人获得 `bounty`（100 SBC）；
- 评价 5 分触发质量奖励 `100 × 2% = 2 SBC`；
- 平台服务费 5 SBC 入账；
- 任务 `state=SETTLED`；
- 账本新增流水，哈希链串联。

> 并发重复调用 `verify` 时，第二次返回 `409 SETTLEMENT_CONFLICT`，余额只变一次（`settlement_guards` 保证）。

### 5.6 查看账本

```bash
# 接单人 user_id 从 me 接口取
curl -s -b $JAR_SOL "$BASE/api/auth/me" | tee /tmp/me.json
SOLVER_ID=$(python -c "import json;print(json.load(open('/tmp/me.json'))['data']['user']['user_id'])")

curl -s -b $JAR_SOL "$BASE/api/ledger/$SOLVER_ID"
```

### 5.7 争议路径（可选）

```bash
# 接单人发起争议
curl -s -b $JAR_SOL -X POST "$BASE/api/tasks/$TASK_ID/dispute" \
  -H 'Content-Type: application/json' -H "X-CSRF-Token: $CSRF_SOL" \
  -d '{"event_id":"evt-sol-003","reason":"发布方长期未验收"}'

# 管理员裁定（resolution: pay_solver / refund_publisher / close）
curl -s -b $JAR_ADM -X POST "$BASE/api/tasks/$TASK_ID/dispute" \
  -H 'Content-Type: application/json' -H "X-CSRF-Token: $CSRF_ADM" \
  -d '{"event_id":"evt-adm-003","action":"resolve","resolution":"pay_solver","reason":"举证充分"}'
```

## 六、用户版操作指南

入口：`https://sambon.net/`（hash 路由 SPA）。

| 路由 | 页面 | 功能 |
|---|---|---|
| `#/hall` | 悬赏大厅 | 浏览可接任务，按分类/赏金筛选，查看任务详情 |
| `#/rank` | 赏金猎人榜 | 任务榜与猎人榜，等级/称号/奖牌 |
| `#/publish` | 发布悬赏 | 填写标题、描述、分类、赏金、验收标准、时限 |
| `#/mine` | 我的委托 | 我发布的 / 我接单的任务，按状态操作 |
| `#/wallet` | 猎人金库 | SBC 余额与流水明细 |
| `#/task/:id` | 任务详情 | 详情与按状态可用动作 |
| `#/auth` | 登录 / 注册 | 邮箱 + 口令；注册选发布方或接单人 |

**发布方操作顺序**：发布 → 等审核 → 等推送 → 收到接单 → 验收（approve / reject）→ 评价。

**接单人操作顺序**：大厅浏览 → 接单 → 进行中 → 提交成果 → 等验收 → 金库查看入账。

**通用功能**：
- 右上角「中 / EN」切换语言。
- 关闭个性化推荐后按时间 + 距离中性排序（服务端强制生效）。
- 「数据与账号」可导出 JSON、删除账号（需输入 `DELETE` 确认）。

## 七、运营台操作指南

入口：`https://sambon.net/product`（需 admin 登录）。

| 标签 | 内容 |
|---|---|
| **工作台** | 待审核队列、待处理争议、风控工单、任务详情与动作面板 |
| **运维** | 指标、审计日志、风控清单、备份、账本锚点、定时作业 |

### 7.1 日常巡检清单

1. **健康**：`GET /api/health` → `mode=production`、`status=healthy`。
2. **待审核队列**：`GET /api/admin/queue`，逐条审核（approve / reject）。
3. **争议**：`GET /api/admin/queue` 中的争议项，按举证裁定（pay_solver / refund_publisher / close）。
4. **风控**：`GET /api/admin/risk`，逐条处置（`POST /api/admin/risk/resolve`），不可批量自动放行。
5. **指标**：`GET /api/admin/metrics`，关注发布量、完成率、异常率。
6. **审计**：`GET /api/admin/audit`，抽查敏感操作。

### 7.2 超时任务

定时作业（`POST /api/admin/cron`）扫描超时任务，**只生成人工确认工单**，不会自动验收或结算。管理员在运营台逐条处理。

### 7.3 操作红线

- 审核、推送、争议裁定、风控处置**必须人工确认**，无批量自动通道。
- 验收由发布方本人执行，管理员不代验收（`auto_accept` 仅用于超时工单的人工触发场景）。
- 模型输出（`model_decision`）恒为 `null`，不参与裁决。

## 八、每日多智能体运营

### 8.1 用途

以多个账号每日发布 10 个任务、完成 1–2 个，保持平台活跃并持续验证全链路。

### 8.2 本地手动运行

```bash
API_BASE=http://127.0.0.1:8788 \
PUBLISHER_ACCOUNTS='[{"email":"pub1@example.com","password":"Passw0rd!2026","display_name":"发布甲"},{"email":"pub2@example.com","password":"Passw0rd!2026","display_name":"发布乙"}]' \
SOLVER_ACCOUNTS='[{"email":"solver1@example.com","password":"Passw0rd!2026","display_name":"猎人甲"},{"email":"solver2@example.com","password":"Passw0rd!2026","display_name":"猎人乙"}]' \
DAILY_PUBLISH_COUNT=10 DAILY_COMPLETE_COUNT=2 \
npm run daily
```

输出：`ops/daily-agents/reports/YYYY-MM-DD.json`（已 gitignore，不入库）。摘要字段：

```json
{
  "registered_accounts": 4,
  "published_count": 10,
  "completed_count": 2,
  "ledger_checks_passed": 2,
  "anomaly_count": 0,
  "red_line_404_count": 0,
  "result": "OK"
}
```

### 8.3 云端定时（GitHub Actions）

工作流：`.github/workflows/daily-agents.yml`，每日 UTC 01:00（北京 09:00）+ 手动触发。

需在仓库 **Settings → Secrets and variables → Actions** 配置：

| Secret | 值 |
|---|---|
| `ADMIN_EMAIL` | 管理员邮箱 |
| `ADMIN_PASSWORD` | 管理员口令 |
| `PUBLISHER_ACCOUNTS` | 发布方账号 JSON 数组 |
| `SOLVER_ACCOUNTS` | 接单方账号 JSON 数组 |

> 账号首次运行自动注册，之后复用。凭据只经 Secrets 注入，不进入代码与日志。

### 8.4 运营边界

- 脚本自动执行「审核 + 推送」两步，因为生产站没有其他管理员在线值守时，任务无法进入可接单状态。该行为由平台运营方决策并承担。
- 脚本**绝不调用 `auto_accept`**；验收始终由发布方本人 `approve`。
- 争议、退款、处罚、风控处置脚本一概不碰。
- SBC 8 条资产化端点脚本不调用，运行后校验其仍为 404。

## 十、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `mode=demo`、写操作 `503 WRITE_LOCKED` | 未绑定 D1，或变量名不是 `DB` | 检查 Settings → Functions → D1 bindings，变量名必须为 `DB` |
| `/api/health` 404 | `_routes.json` 缺失或 Functions 未编译 | 确认 `functions/api/[[path]].js` 存在且目录为仓库根 |
| 注册返回 `WEAK_PASSWORD` | 开启强口令后不足 12 位/3 类字符 | 提高口令强度或关闭 `ENFORCE_STRONG_PASSWORD` |
| 注册返回 `DISPOSABLE_EMAIL` | 使用一次性邮箱域名 | 换常规邮箱 |
| 发布返回 `INSUFFICIENT_BALANCE` | 可用 SBC 不足以冻结「赏金 + 5%」 | 降低赏金或先获得 SBC |
| 发布返回 `COMPLIANCE_BLOCKED`（422） | 文案命中违禁词 | 修改标题/描述/验收标准 |
| 写操作 `403 FORBIDDEN` | 角色越权 | 用对应角色账号操作 |
| 写操作 `401` | 未登录或 Cookie 丢失 | 重新登录，确认携带 Cookie |
| `/api/admin/cron` 503 | 未配 `CRON_SECRET` | 配置该变量并在请求头带 `X-Cron-Secret` |
| 重复结算 `409 SETTLEMENT_CONFLICT` | 已结算/终局在途（防双花生效） | 正常行为，勿重试 |
| 页面白屏 | 产物未重建 / JS 报错 | `npm run build`，浏览器控制台看报错 |
| 用户版是 L0 演示而非真实数据 | 访问了 `/index.html` 或 `/demo` | 走 `/` 或 `/app` |
| 部署后文案未更新 | Cloudflare 缓存 | 强制刷新或等构建完成，用带版本参数的 URL 核验 |

## 十二、变更与发布流程

```
分支开发 → 本地 npm run build && npm test 全绿
        → 提交（语义化信息）
        → 推送分支 → 合并 main
        → Cloudflare 自动构建部署
        → curl /api/health 核验
        → 运营台抽查一个任务闭环
```

### 12.1 数据库变更

1. 改 `prod/lib/schema.js`（用 `CREATE TABLE IF NOT EXISTS` 与幂等 `ALTER TABLE ... ADD COLUMN` 保护）。
2. `npm run build` 重新生成 `schema.sql`。
3. 在生产执行 `npx wrangler d1 execute <库名> --file=schema.sql --remote`。
4. 回归 `npm run test:production`。

### 12.2 回滚

- 代码：`git revert <commit>` 后推送，Cloudflare 自动回滚部署。
- 数据：D1 无自动回滚，变更前先 `wrangler d1 export` 备份。

### 12.3 发布检查表

- [ ] `npm run build` 产物已更新
- [ ] `npm test` 退出码 0
- [ ] `schema.sql` 已同步（如有表结构变更，且已在生产执行）
- [ ] `git push origin main` 已触发部署
- [ ] `/api/health` 返回 `production / d1 / healthy`
- [ ] 运营台可登录，待审核队列可见
- [ ] 抽查一个任务可正常发布 → 审核 → 接单 → 提交 → 验收 → 结算
