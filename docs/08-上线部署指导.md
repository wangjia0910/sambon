### 2.3 路径 B：自建服务器 / 域名 sambon.net（历史习惯沿用）

```bash
# 1) 在服务器拉取代码（GitHub 已公开）
git clone https://github.com/wangjia0910/sambon.git && cd sambon

# 2) 以指定端口常驻（Node 22+，零依赖，无需 npm install）
PORT=8080 node src/server.mjs

# 3) 反向代理：把 https://sambon.net / 与 /api/ 一并转发到 127.0.0.1:8080，并配置 HTTPS
# 4) 进程守护：systemd / pm2 / 容器任选其一，配置崩溃自动重启
```

**三个必须避开的坑**：

1. **不要只把 `web/index.html` 丢到静态托管（Cloudflare Pages / OSS）**。操作台所有按钮都调 `/api/*`，静态托管下会全部 404，页面看起来能开但实际是死的。要托管就托管整个 Node 服务。
2. **Cloudflare Pages 不跑长驻 Node 进程**；若坚持用 Cloudflare，需改写为 Workers 或改用 VPS / 容器。改写属于 §4 的 P0 工作量，不是配置问题。
3. **内存存储 + 进程守护 = 每次重启数据清空**。演示可接受，接真实用户绝不可接受（见 §4 第 1 项）。

域名解析、HTTPS 证书、防护与备案按公司既有流程办；本指导不代替运维方案。

## 8. 红线与常见误区

1. **不得**把 L0 演示预览链接说成「平台已上线 / 已开放注册 / 已开始运营」；对外表述只能是「项目原型在线演示」。
2. **不得**在页面、README、宣传材料出现 SBC 可交易、可兑付、升值、收益等表述；SBC 始终定位为平台内贡献积分凭证。
3. **不得**跳过 G6 直接灰度；**不得**为赶进度放宽 §5 任一阈值。
4. **不得**把真实手机号 / 身份证写进演示数据或事件日志；**不得**让模型直判结算与争议。
5. **不得**只部署静态页（§2.3 坑 1）；**不得**在内存存储状态下接真实用户。
6. **不得**用裸 `--force` 覆盖仓库；旧命理项目完整备份在 `E:\SKILLS\_sambon-legacy-backup.git`，恢复用 `git clone` 即可。
7. **不得**把 PAT 写入 `.git/config`、脚本或文档；一次性注入、用完轮换。
