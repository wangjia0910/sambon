## 2. 架构与数据

```
浏览器 https://sambon.net/      （中 / EN，Cookie 同意，L1 声明，人工确认弹窗）
   │
   ├─ 静态产物 cloudflare/（15 文件，_redirects 把 / 重写到 prod.html）
   │
   └─ /api/*  → functions/api/[[path]].js（唯一路由文件）
                  └─ prod/lib/api.js（41 个端点编排）
                       ├─ domain.js / hash.js ← src/*.mjs 逐字节同步（口径唯一真源）
                       ├─ auth.js      PBKDF2 / 会话 / CSRF / RBAC / 限流
                       ├─ db.js        D1 适配 + ensureSchema（建表 + 幂等补列）
                       ├─ schema.js    表结构唯一真源 → schema.sql
                       ├─ notify.js    通知 outbox + HMAC Webhook（降级 queue_only）
                       ├─ llm.js       可配置模型 + 规则降级 + model_decision:null
                       ├─ jobs.js      5 个定时作业（只出人工工单）
                       ├─ observability.js 指标 / 结构化日志 / 账本完整性
                       ├─ risk.js      风控评分（只标记）+ 人工处置
                       ├─ security.js  邮箱验证 / GPC / 口令策略 / 会话轮换

```

**表结构 `sambon-prod-schema-v2.0`**：v1.0 的 13 张表全部保留；新增 `email_verifications` / `notifications` / `dispatch_feedback` / `metrics` / `risk_flags` / `backups` 6 张；`users` 增 `email_verified / locale / gpc_enabled / failed_logins / locked_until / last_seen_at / password_changed_at` 7 列；`tasks.version` 用于 CAS。

## 5. 正式运营就绪门禁（`tests/readiness-check.mjs`）

### 5.1 为什么需要它

「可正式上线运营」里有一半动作**在任何代码库里都做不到**：绑定 D1、签 DPA、请律师出书面意见、买保险、演练灾备、有权签字人签发 Go。把它们写成复选框再自动打勾，就是造假。本门禁把两类事项严格分开：

- **[A] 代码能力 16 项**：只读静态扫描（表结构 / 红线 / 无默认口令 / 模型不决策 / 降级不伪造 / cron 不自动结算 / CAS / 人工闸门 / GDPR / i18n / 安全头 / PII / demo 降级 / 回归齐备 / 回归覆盖 / 契约登记），命中即核销。
- **[B] 外部闸门 20 项**：读取 `ops/readiness.json`，每项必须同时具备 `verified:true`、`by`、`at`、`evidence`（均非空字符串）才计核销。**缺任一字段、文件或字段造假式空值，一律 UNVERIFIED**。

### 5.2 用法

```bash
node tests/readiness-check.mjs            # 打印门禁报告
node tests/readiness-check.mjs --strict   # NOT READY 时退出码 1（供 CI）
node tests/readiness-check.mjs --init     # 从模板生成 ops/readiness.json（不入库）
npm run check:ready
```

`ops/readiness.template.json` 入库（20 个 ID 与说明）；`ops/readiness.json` 由 `.gitignore` 排除，含人工签字与内部证据路径。

## 6. 定时任务怎么真正跑起来

Cloudflare **Pages Functions 不支持 `scheduled` handler**（那是 Workers 的能力），因此本系统用「HTTP 触发 + 外部调度器」，这是可验证、可运维且不依赖未确认平台能力的方案。

```bash
# 由外部调度器每 15 分钟调用一次（密钥只放调度器侧，不落库、不进前端）
curl -X POST https://sambon.net/api/admin/cron \
  -H 'Content-Type: application/json' \
  -H "X-Cron-Secret: $CRON_SECRET" \
  -d '{"dry_run":false}'
```

可选调度器：独立 Cloudflare Worker（Cron Triggers）、GitHub Actions `schedule`、任意可信的定时 HTTP 服务。`dry_run:true` 只统计不写入，便于上线前核对。生产台「运维 → 定时任务」也提供手动触发入口（需填入密钥）。

> 即使调度器长期不跑，系统也只是**不产生超时提醒工单**，不会自动结算、不会自动裁定、不会丢数据——人工闸门始终保留。

| 真实法币支付 / 充值 / 提现 / 资金托管 | SBC 是平台内贡献积分；接入法币会把它变成支付工具或类金融产品，直接违反契约 §10、`COMPLIANCE.md` 与 D-12 下的 V2-O 第 5 组。**「完全体」不等于功能越多越好** |
| 公链存证 / 代币 / 二级市场 | 账本哈希链是本地可审计摘要；零 PII、零任务正文。上公链会引入不可删除的个人数据风险（GDPR Art.17 冲突） |
| 自动验收 / 自动结算 / 自动裁定 / 自动处罚 | 用户一贯要求保留人工回访确认闸门；本轮 cron 只生成工单，`risk.blocked` 恒 false，模型 `model_decision` 恒 null |
| Durable Objects / 跨区域多写 | Pages Functions 无法定义 DO class；当前以 D1 `version` CAS 覆盖单库并发正确性。跨区域多活需架构级重新评审，不在本轮 |
| 内置默认账号 / 口令 | 首名 admin 由 `ADMIN_BOOTSTRAP_TOKEN` 一次性引导，用完移除变量 |
| 自称「已上线 / 已开放注册 / 已完成合规 / 无需任何合规义务」 | 见 §9 |
