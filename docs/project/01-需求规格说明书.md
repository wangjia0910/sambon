## 1. 引言

### 1.1 编写目的

本文档定义「三宝殿 · 悬赏互助平台」面向真实用户的 Web 产品站的**完整需求**，作为产品设计、研发实现、测试验收与法务合规评审的共同依据。目标读者为产品经理、前后端研发、测试、运营与法务合规人员。

本产品站在既有生产系统（Pages Functions + D1，41 个 API 端点）之上，新增**面向真实用户（Publisher / Solver）的前端产品入口**，与既有内部操作台（`/prod`）、L0 演示台（`/index`）并存，三通道互不干扰。

## 2. 业务背景与定位

### 2.1 业务背景

方案 v1.0 §1.1 将平台定位为：「用大模型驱动的匹配与调度，把非标准化的悬赏任务，推送给最可能按时完成的人；用 SBC 积分体系度量贡献并给予平台内权益。」其关键差异在于——推的是**有履约成本的任务**而非内容，一次误推送会消耗接单人注意力与发布方时效，失败任务需要人工仲裁，供给方是人而非无限库存，必须做打扰控制与公平性约束。

方案 §1.2 明确不做：自营履约、内容社区/IM 自由聊天、SBC 交易/转让/法币兑换/二级市场/理财化宣传、付费买自然排序权重、大模型直接决定最终推送名单与结算结果。

### 2.2 产品定位

本产品站是三宝殿的**唯一面向真实用户的 Web 主入口**，承担三类核心诉求：

| 角色 | 核心诉求 | 产品承载 |
|---|---|---|
| Publisher | 快、便宜、别被骗 | 发布悬赏 → 查看接单 → 验收/驳回 → 结算与评价 |
| Solver | 就近/类目精准、单多、结算快、少纠纷 | 浏览榜单 → 接单 → 履约提交 → 积分到账 → 评价 |
| 平台侧 | 可管控、可回放、可对账 | 人工闸门（审核/推送/裁定/风控/备份/锚定/cron） |

北极星指标：任务有效完成率（有效完成任务数 / 已接单任务数），MVP ≥ 70% / 完整版 ≥ 82%（方案 §3.5）。反向护栏：平均每任务推送人数 ≤ 25、通知关闭率 ≤ 1.5%、接单人 30 日留存。

### 2.3 相对原方案的收敛

依据 CONTRACT §11 D-10 / D-12 / D-13 / D-14，本轮相对方案 v1.0 作如下收敛（差异均已在契约登记，方案基线不改写）：

| 项 | 方案 v1.0 原形态 | 本轮收敛形态 | 契约依据 |
|---|---|---|---|
| 产品形态 | 微信小程序 + APP 先行，P3 智能硬件 | **Web 单端**（Cloudflare Pages Functions + D1）为唯一交付形态 | D-10、D-13 |
| 服务地域 | 面向中国境内公众 | **中国境外（海外市场）**，Cloudflare 全球边缘接入 | D-12 |
| 备案口径 | 算法/区块链备案为上线闸门 | 两项境内备案 + ICP 归档为触发式预案；改判 V2-O 境外发布合规基线 | D-12 |
| 后端 | L0 内存原型 | **生产系统**：41 端点、19 张表、账号级开关、会话/CSRF/RBAC、账本哈希链 | D-13、D-14 |
| 站点入口 | 操作台 `GET /` | 用户版主入口 `/`；操作台 `/prod`；L0 演示 `/index` | 本轮新增 |
| 大模型 | 规则兜底 | LLM 可配置真实接入 + 未配置如实降级（`degraded`），人工兜底不直判 | D-14 |
| 运营许可 | — | 代码 READY（117/117）≠ 正式运营许可（外部 20 项 0/20 → NOT READY） | D-14 |

> **明确不在本期**：小程序 / APP / 智能硬件（D-10 移出本轮交付，列后续待评审）；真实支付 / 公链存证 / 自动结算 / 跨区域多活（D-14 明确不做）。

### 2.4 形态与部署

- **Web 单端**：浏览器原生 ESM 零依赖前端，API 同源相对路径 `/api/*`。
- **部署**：Cloudflare Pages，`git push origin main` → Git 集成自动部署，构建输出目录 `cloudflare`（CONTRACT §11 D-13）。
- **持久化**：D1 数据库，绑定变量名 `DB`；未绑定时降级为 `mode=demo`，写操作 503（详见 `02-系统架构设计.md`）。
- **三通道并存**：`/` 用户版产品站、`/prod` 内部操作台、`/index` L0 演示台、`/legal.html` 合规披露页。

## 3. 用户画像与角色

### 3.1 角色定义与权限

系统采用 RBAC 三角色（`prod/lib/auth.js:requireRole`），加访客：

| 角色 | 标识 | 注册方式 | 核心能力 | 人工闸门权限 |
|---|---|---|---|---|
| 访客 Guest | 未登录 | 无需注册 | 浏览合规披露页 `/legal.html`；被引导登录 | 无 |
| 发布方 Publisher | `publisher` | 自行注册（`POST /api/auth/register`） | 发布/撤回任务、验收/驳回、发起争议、查看账本、导出 | 不可审核/裁定（任务归属方仅可验收自己任务） |
| 接单人 Solver | `solver` | 自行注册 | 浏览榜单、接单、提交成果、发争议、曝光回执、查看账本 | 不可裁定 |
| 管理员 Admin | `admin` | `POST /api/admin/bootstrap` 引导创建（首名凭 `ADMIN_BOOTSTRAP_TOKEN`） | 全部人工闸门：审核、推送、超时自动验收、争议裁定、风控处置、备份、锚定、cron、指标/审计 | 全部，且动作写 `audit_log` |

### 3.2 关键权限矩阵（对齐 `docs/12` §4.2）

| 动作 | 访客 | Publisher | Solver | Admin |
|---|:--:|:--:|:--:|:--:|
| 浏览任务大厅/榜单 | ✓ | ✓ | ✓ | ✓ |
| 发布任务 `POST /api/tasks` | ✗ | ✓ | ✗ | ✓ |
| 接单 `POST /api/tasks/:id/accept` | ✗ | ✗ | ✓ | ✗ |
| 验收/驳回 `POST /api/tasks/:id/verify` | ✗ | ✓（仅本人任务） | ✗ | ✓（含 `auto_accept`） |
| 发起争议 `action:open` | ✗ | ✓（相关方） | ✓（相关方） | ✓ |
| 争议裁定 `action:resolve` | ✗ | ✗ | ✗ | ✓ |
| 平台审核 `POST /api/tasks/:id/review` | ✗ | ✗ | ✗ | ✓ |
| 触发推送 `POST /api/tasks/:id/dispatch` | ✗ | ✗ | ✗ | ✓ |
| 撤回任务 `POST /api/tasks/:id/cancel` | ✗ | ✓（本人） | ✗ | ✓ |
| 查看账本 `GET /api/ledger/:userId` | ✗ | ✓（仅本人） | ✓（仅本人） | ✓（全部） |
| 备份/锚定/风控/cron | ✗ | ✗ | ✗ | ✓ |

### 3.3 用户旅程

**发布方旅程**（方案 §1.5）：注册/登录 → 选择类目 → 填标题/描述/验收标准/地点或线上/deadline/赏金 → 合规预检 + 余额预校验 → `PENDING_REVIEW` → 平台审核通过冻结 → 查看接单 → 验收/驳回 → 结算与评价。

**接单人旅程**：注册/登录 → 浏览任务榜/任务大厅 → 收到推送（含理由）→ 独占窗口接单 → 履约 → 提交成果（正文 PII 脱敏）→ 验收通过 → 积分到账、榜单更新 → 评价。

### 3.4 场景与验收侧重

| 场景 | 特征 | 推送策略 | 验收侧重 |
|---|---|---|---|
| S1 本地即时跑腿 | 强 LBS、< 2h、金额低、非技能 | 定向派单 K=8、独占 3 min | 首次接单时长、准时率 |
| S2 技能型悬赏 | 弱 LBS、1–7 天、需认证 | 邀请制 + 语义精排 K=12、独占 15 min | 验收通过率、争议率 |
| S3 众包/竞赛制 | 多接单人并行、按结果选优 | 广播抢单 K=30、分 3 批 | 有效成果数、单人打扰成本 |

> 本期用户产品站以 **S1 / S2 单接单人闭环**为主；S3 多中标为 P2。

## 4. 功能需求

> 编号规则 `FR-x`。每条含编号、描述、优先级、验收口径。所有验收口径可测、带数值；引用 CONTRACT v0.2 口径不另造。写操作均要求同源会话 + CSRF（`X-CSRF-Token`），非公开端点未登录返回 `401 UNAUTHORIZED`。

### 4.1 账号、身份与邮箱验证

| 编号 | 描述 | 优先级 | 验收口径 |
|---|---|:--:|---|
| FR-01 | 用户注册：使用邮箱 + 密码 + 显示名 + 角色（`publisher`/`solver`）注册；密码 10–128 位；一次性邮箱域名拦截；GPC/DNT 信号注册时即生效（个性化默认关闭）；可选 `locale`（`zh-CN`/`en`）。 | P0 | `POST /api/auth/register` 返回 `201` + 用户视图 + 会话 Cookie；邮箱格式/长度/角色校验失败返回对应错误码；重复邮箱 `EMAIL_TAKEN` 409；注册即由生态激励池记账发放初始额度（默认 1000 SBC，非资产、不可兑付），两腿守恒；不采集真实 PII。 |
| FR-02 | 登录与会话：邮箱 + 密码登录；口令 PBKDF2-SHA256（默认 120000 轮）派生校验；连续失败锁定 15 min；会话 token 仅以 SHA-256 摘要入库，httpOnly + Secure + SameSite=Lax Cookie；响应统一错误码避免账号枚举。 | P0 | `POST /api/auth/login` 下发会话 Cookie + `csrf_token`；错误凭证统一 `INVALID_CREDENTIALS` 401；锁定返回 `ACCOUNT_LOCKED` 423；`GET /api/auth/me` 返回当前用户视图；`POST /api/auth/logout` 清除会话。 |
| FR-03 | 邮箱验证：注册后生成验证令牌，令牌**只经通知队列送达**，不在 HTTP 响应下发（本地回归可显式 dev echo）；支持重新发送；可配置是否强制验证。 | P0 | `POST /api/auth/verify-email`、`POST /api/auth/resend-verification` 可用；`verification_required` 状态可见；令牌不出现在生产响应体。 |
| FR-04 | CSRF token 获取：会话建立后由登录/注册响应下发 `session.csrf_token`，前端所有写请求回传 `X-CSRF-Token`。 | P0 | 未带/错误 token 返回 `CSRF_FAILED` 403；跨源写请求返回 `CROSS_ORIGIN_BLOCKED` 403；公开端点（注册/登录/验证/cron/同意）不走 CSRF 校验。 |

### 4.2 发布与任务生命周期

| 编号 | 描述 | 优先级 | 验收口径 |
|---|---|:--:|---|
| FR-05 | 发布悬赏：填写必填字段 `title / description / category / bounty / acceptance_criteria`，可选 `deadline_hours`（1–720，默认 48）、`online`（默认 true）、`radius_km`、`required_skills`、`difficulty`、`contact`；提交时做**合规预检 + 余额预校验**，仅校验、不冻结、不写流水。 | P0 | `POST /api/tasks` 返回 `201` + `task`（含 `state: PENDING_REVIEW`）+ `compliance`；违禁词命中 `COMPLIANCE_BLOCKED` 422 并发 `RiskBlocked`；可用 SBC < 赏金 + 5% 服务费时 `INSUFFICIENT_BALANCE`；联系方式一律虚拟号占位（`virtual_contact`）；必填缺失 `MISSING_FIELD`；赏金 0–1,000,000。 |
| FR-06 | 平台审核（人工闸门）：管理员对待审核任务复核，通过进入 `PUBLISHED` 并冻结赏金 + 5% 服务费（可用→冻结，写 `CreditFrozen`），驳回进入 `REJECTED`。冻结时点为审核通过（CONTRACT §11 D-01）。 | P0 | `POST /api/tasks/:id/review` `decision: approve/reject`；冻结仅在审核通过发生一次；重复 `event_id` 不重复记账；非法迁移 `ILLEGAL_TRANSITION`；审核动作写 `audit_log`。 |
| FR-07 | 触发推送（人工闸门）：管理员对已发布任务触发推送，支持 `dry_run` 预览；产出 Top-K 候选 + 分数 + `reason_codes` + `weight_version=v1.0`，按批次触达。 | P0 | `POST /api/tasks/:id/dispatch`；硬过滤先于打分；候选字段完整率 100%；`dry_run` 只预览不落库不改状态；模型不可用自动降级规则引擎、推送不中断；落 8 类留痕字段。 |
| FR-08 | 接单（并发原子锁）：Solver 在独占窗口接单，服务端以 D1 `version` CAS 原子占位，先到先得；冻结转托管（裁定前不转付）；榜单 ≤ 1s 下架。 | P0 | `POST /api/tasks/:id/accept`；并发仅 1 个成功，败者返回 `CONCURRENT_CONFLICT` 409 / `TASK_ALREADY_ACCEPTED` 409 且不产生孤立托管流水；被硬过滤 `SOLVER_FILTERED` 422；赏金未冻结不可接单；发 `TaskAccepted` / `CreditChanged`。 |
| FR-09 | 履约提交（PII 脱敏）：指派 Solver 提交成果正文，先经 `sanitizeSubmissionText()` 脱敏（证件号/手机号正则）后落库，原始明文不存储、不进事件日志。 | P0 | `POST /api/tasks/:id/submit`；状态 `ACCEPTED/IN_PROGRESS/SUBMITTED → SUBMITTED`；非指派人 `NOT_ASSIGNED_SOLVER` 403；返回 `result_preview`（脱敏）与 `result_pii_redacted`；正文 ≤ 20000 字符。 |
