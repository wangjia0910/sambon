## 1. 全局交互规范

### 1.1 响应包络

| 场景 | 结构 | 前端处理 |
|---|---|---|
| 成功 | `{ ok:true, data:<对象>, error:null }` | 取 `data` 渲染；写操作后 `toast('操作成功')` 并按状态刷新 |
| 失败 | `{ ok:false, data:null, error:{ code, message } }` | 按 `error.code` 分支处理，展示 `error.message`，不回显堆栈/SQL/PII |

**统一错误码与前端动作**（取自 `response.js` 与各 handler）：

| code | HTTP | 前端动作 |
|---|---|---|
| `UNAUTHORIZED` | 401 | 清除本地会话态，跳转 V7 登录；登录后回原视图 |
| `CSRF_FAILED` / `CROSS_ORIGIN_BLOCKED` | 403 | 提示「请刷新页面后重试」，重新拉取 `csrf_token` |
| `FORBIDDEN` | 403 | 提示无权限，隐藏对应操作按钮 |
| `NOT_FOUND` | 404 | 展示空态/资源不存在 |
| `ILLEGAL_TRANSITION` | 400 | 提示当前状态不允许该操作，刷新任务状态 |
| `TASK_ALREADY_ACCEPTED` / `CONCURRENT_CONFLICT` | 409 | 提示「已被接单，请刷新」，刷新详情 |
| `ACTIVE_TASKS_EXIST` | 409 | 注销页提示先完成进行中任务 |
| `EMAIL_TAKEN` / `INVALID_CREDENTIALS` / `ACCOUNT_LOCKED` | 409/401/423 | 表单字段级/全局错误提示 |
| `COMPLIANCE_BLOCKED` / `SOLVER_FILTERED` | 422 | 展示具体原因，阻断提交 |
| `INSUFFICIENT_BALANCE` | 400 | 引导至 SBC 账户说明（非资产、初始额度） |
| `REJECT_LIMIT` | 400 | 提示转争议/人工 |
| `RATE_LIMITED` | 429 | 提示稍后重试，禁用按钮倒计时 |
| `PERSISTENCE_NOT_CONFIGURED` | 503 | 顶部显示「演示模式」横幅，禁用所有写按钮 |
| `INTERNAL_ERROR` | 500 | 通用「服务内部错误，请稍后重试」 |

### 1.2 CSRF token 获取

- 会话建立后，`POST /api/auth/register` / `POST /api/auth/login` 响应 `data.session.csrf_token`。
- 前端保存该 token，所有写请求（POST/DELETE）在请求头回传 `X-CSRF-Token: <csrf_token>`。
- 读请求（GET）无需 CSRF；公开端点（注册/登录/验证/cron/同意）不校验 CSRF。

### 1.3 401 处理

- 任意 API 返回 401 → 前端清除会话标记 → 跳转 `#/auth`（保留 `redirect` 参数）→ 登录成功后回填。
- 首次加载：`GET /api/auth/me` 判定登录态；未登录时顶部显示「Sign in」，访客可浏览 V1/V6/V7 与披露页。

### 1.4 demo 模式写锁

- 启动时 `GET /api/health`：`mode=demo` 或写请求首次返回 503 → 顶部渲染橙色横幅「演示模式：未绑定持久化，写操作不可用」，并链接 `/index.html`。
- 所有写按钮置灰禁用；读视图正常展示（榜单/详情回退为可读快照或空态）。

### 1.5 双语文案

- `locale` 由 `GET /api/auth/me`（登录）或默认 `en`（未登录）决定；切换经 `POST /api/me/locale`（登录用户）。
- 所有文案、错误提示、状态标签、toast 提供 `zh-CN` / `en` 两套；`/api/config.locales` 暴露支持列表。
- 状态标签映射（示例）：`PUBLISHED`→「已发布 / Published」、`DISPUTED`→「争议中 / Disputed」、`SETTLED`→「已结算 / Settled」。

### 1.6 toast 反馈

- 所有写操作成功/失败用 `aria-live="polite"` 的 toast 反馈；成功绿色、失败红色、中性信息蓝色。
- 二次确认类操作（取消、注销、举报）用模态弹窗（人工闸门二次确认），确认后才发请求。

### 1.7 可访问性

- 表单控件均有 `<label>` 与 `aria-describedby` 错误提示；导航/按钮语义化。
- 键盘可达、焦点可见；图标按钮有 `aria-label`；toast 用 `aria-live`。
- 空态/加载态/错误态均有清晰文案，双语齐全。

### 1.8 人工闸门与合规提示

- 审核、推送、自动验收、争议裁定为 admin 人工闸门，用户端只展示「待审核/裁定中」状态与进度，不得出现「模型已自动裁定」类文案。
- 全站显著展示 SBC 非资产声明与 AI 降级披露（取自 `/api.config.sbc_notice` / `ai_disclosure`）。

## 2. V1 任务大厅（首页）

路由 `#/hall`。这是访客与登录用户的默认落地页，展示可接任务与两类榜单入口。

### 2.1 功能点表

| 编号 | 功能点 | 说明 |
|---|---|---|
| V1-F01 | 榜单 tab 切换 | 顶部 tab：任务榜（Task Rank）/ 用户榜（User Rank），默认任务榜 |
| V1-F02 | 类目筛选 | 按 `category` 下拉筛选（如设计/翻译/跑腿/维修） |
| V1-F03 | 状态筛选 | 按 `state` 筛选（`PUBLISHED`/`DISPATCHING`/`IN_PROGRESS` 等） |
| V1-F04 | 搜索 | 按标题关键词前端过滤（基于已加载任务列表） |
| V1-F05 | 任务卡片字段 | 展示 `title / category / bounty / state / deadline / radius_km / rank_score / top_factors` |
| V1-F06 | 中性排序提示 | 关闭个性化时展示「按时间 + 距离中性排序」提示（`mode=neutral`） |
| V1-F07 | 榜单口径说明 | 展示 `rank_weight_version` 与权重，付费置顶不进自然排序声明 |
| V1-F08 | 空态/加载态 | 加载中骨架屏；无任务展示空态与发布引导 |

### 2.2 交互流程

1. 进入 `#/hall` → 并行请求 `GET /api/tasks`（任务列表）与 `GET /api/leaderboard/tasks`（任务榜）。
2. 渲染任务卡片列表与榜单 tab；未登录用户仍可读。
3. 用户切换类目/状态/输入搜索词 → 前端即时过滤，无额外请求。
4. 切换用户榜 tab → 请求 `GET /api/leaderboard/users` 渲染。
5. 点击任务卡片 → 进入 V3 任务详情（`#/task/:id`）。
6. 若 `/api/config.personalized_enabled=false` → 展示中性排序提示，榜单 `rank_score:null`、`reason_codes` 为 `NEUTRAL_*`。

### 2.3 涉及的 API

| API | 用途 | 关键返回字段 |
|---|---|---|
| `GET /api/tasks` | 任务大厅列表 | `count / tasks[]{task_id,title,category,bounty,state,deadline}` |
| `GET /api/leaderboard/tasks` | 任务榜 | `rank_weight_version / weights / mode / items[]{rank,rank_score,top_factors}` |
| `GET /api/leaderboard/users` | 用户榜 | `weights / items[]{rank,net_sbc,rank_score}` |
| `GET /api/config` | 权重版本、个性化状态、降级状态 | `personalized_enabled / algorithm_degraded / rank_weight_version / sbc_notice` |

### 2.4 状态/错误分支

| 分支 | 处理 |
|---|---|
| `401` | 读接口一般公开；若后端要求登录则跳 V7 |
| `503` demo | 显示演示横幅，榜单可能为空，写操作禁用 |
| 榜单快照降级 | 展示 `mode/note` 提示与上次快照时间，不展示失效任务 |
| 空列表 | 展示空态「暂无可接任务」+ 发布引导（Publisher） |
| 中性排序 | `mode=neutral` 时隐藏 `rank_score`，展示中性提示 |

## 3. V2 发布悬赏

路由 `#/publish`。仅 Publisher / Admin 可见；Solver 访问时引导切换角色或隐藏入口。

### 3.1 表单字段（对齐 `POST /api/tasks`）

| 字段 | 类型 | 必填 | 前端校验规则 | 后端约束 |
|---|---|:--:|---|---|
| `title` | text | 是 | 非空，≤ 200 字符 | 截断 200；违禁词预检 |
| `description` | textarea | 是 | 非空，≤ 5000 字符 | 截断 5000；违禁词预检 |
| `category` | select | 是 | 从类目白名单选择 | 截断 64 |
| `bounty` | number | 是 | > 0，≤ 1,000,000，两位小数 | `INVALID_BOUNTY` |
| `acceptance_criteria` | textarea | 是 | 非空，≤ 3000 字符 | 违禁词预检 |
| `deadline_hours` | number | 否 | 1–720，默认 48 | 截断到 [1,720] |
| `online` | boolean | 否 | 默认 true（线上任务） | `true/false` |
| `radius_km` | number | 否 | ≥ 0，默认 10；线下任务必填 | `Math.max(0,…)` |
| `required_skills` | tags | 否 | ≤ 20 项 | 截断 20 |
| `difficulty` | number | 否 | 0–1，默认 0.3 | `Number(…)` |
| `contact` | — | 否 | 前端不采集真实联系方式 | 一律虚拟号占位 |
| `event_id` | string | 否 | 前端生成 UUID（幂等键） | ≤ 128 字符 |

### 3.2 交互流程

1. 进入表单 → 前端做必填/范围/字符数校验，错误就地标注。
2. 展示合规提示：违禁任务类型清单、SBC 非资产声明、联系方式虚拟号说明。
3. 提交 → `POST /api/tasks`（带 `X-CSRF-Token` 与 `event_id`）。
4. 成功 → toast「已提交审核」→ 跳转 V4 我的任务（状态 `PENDING_REVIEW`）。
5. 失败 → 按 `error.code` 就地提示（违禁词、余额不足、字段缺失）。

### 3.3 涉及的 API

| API | 用途 |
|---|---|
| `POST /api/tasks` | 发布（合规预检 + 余额预校验；仅校验不冻结） |
| `GET /api/auth/me` | 判定发布方身份与可用余额展示 |
| `GET /api/config` | 读取 `sbc_notice` 合规提示 |

### 3.4 状态/错误分支

| 分支 | 处理 |
|---|---|
| 成功 | `201`，`task.state=PENDING_REVIEW`，不冻结、不写流水；发 `TaskPublished` |
| `COMPLIANCE_BLOCKED` 422 | 展示命中违禁词，阻断提交，发 `RiskBlocked` |
| `INSUFFICIENT_BALANCE` | 提示可用 SBC 需 ≥ 赏金 + 5% 服务费（审核通过才冻结） |
| `MISSING_FIELD` / `INVALID_BOUNTY` | 字段级错误提示 |
| `401` / `CSRF_FAILED` | 跳登录 / 提示刷新重取 token |
| `503` demo | 写按钮禁用，提示演示模式 |

## 4. V3 任务详情

路由 `#/task/:id`。展示任务全量信息、角色相关操作与事件回放入口。

### 4.1 功能点表

| 编号 | 功能点 | 角色 | 说明 |
|---|---|---|---|
| V3-F01 | 信息展示 | 全部 | `title / description / category / bounty / service_fee / frozen_total / acceptance_criteria / deadline / virtual_contact / state / reject_count / submit_count / result_preview` |
| V3-F02 | 接单按钮 | Solver | `PUBLISHED/DISPATCHING` 且未被接单时显示「接单」 |
| V3-F03 | 提交成果 | Solver（指派人） | `ACCEPTED/IN_PROGRESS/SUBMITTED` 显示成果提交框，正文提示 PII 脱敏 |
| V3-F04 | 验收/驳回 | Publisher（本人） | `SUBMITTED` 显示通过/驳回（附理由 + 评分） |
| V3-F05 | 发起争议 | 相关方 | `SUBMITTED/IN_PROGRESS` 显示「发起争议」（附理由） |
| V3-F06 | 撤回/取消 | Publisher/Admin | `PENDING_REVIEW/PUBLISHED/DISPATCHING` 显示「撤回」 |
| V3-F07 | 事件回放入口 | 全部 | 链接到事件回放，按 `task_id` 拉取全链路事件 |
| V3-F08 | 自动验收提示 | 全部 | `SUBMITTED` 展示「24h 未操作自动验收」口径说明（admin 手动触发） |

### 4.2 交互流程

1. 进入详情 → `GET /api/tasks`（从列表定位）或按 `task_id` 渲染已缓存任务；按当前用户角色与 `state` 决定显示哪些操作按钮。
2. 接单（Solver）→ 二次确认 → `POST /api/tasks/:id/accept`（原子锁）→ 成功进入 `ACCEPTED`。
3. 提交成果（Solver）→ 输入正文 → `POST /api/tasks/:id/submit`（PII 脱敏）→ `SUBMITTED`。
4. 验收/驳回（Publisher）→ 通过填 `rating`，驳回填 `reason` → `POST /api/tasks/:id/verify` → `SETTLED` 或 `IN_PROGRESS`。
5. 争议（相关方）→ 填 `reason` → `POST /api/tasks/:id/dispute action:open` → `DISPUTED`（全额托管、人工裁定）。
6. 撤回（Publisher/Admin）→ 二次确认 → `POST /api/tasks/:id/cancel` → `REJECTED/CANCELLED` + 退款/分账。
7. 事件回放 → `GET /api/events?task_id=<id>` → 时间线展示各事件 `type/actor/payload/created_at`。

### 4.3 涉及的 API

| API | 用途 |
|---|---|
| `POST /api/tasks/:id/accept` | 接单（version CAS 原子锁） |
| `POST /api/tasks/:id/submit` | 提交成果（PII 脱敏） |
| `POST /api/tasks/:id/verify` | 验收/驳回/自动验收 |
| `POST /api/tasks/:id/dispute` | 发起争议 / 裁定（裁定仅 admin） |
| `POST /api/tasks/:id/cancel` | 撤回/取消 |
| `GET /api/events?task_id=` | 事件回放 |

### 4.4 状态/错误分支

| 分支 | 处理 |
|---|---|
| `TASK_ALREADY_ACCEPTED` / `CONCURRENT_CONFLICT` 409 | 提示已被接单，刷新详情，隐藏接单按钮 |
| `SOLVER_FILTERED` 422 | 展示硬过滤原因（资质/半径/负载/频次/关联） |
| `NOT_ASSIGNED_SOLVER` 403 | 隐藏提交框 |
| `ILLEGAL_TRANSITION` | 隐藏不适用操作，刷新状态 |
| `FORBIDDEN`（非发布方验收/裁定） | 隐藏按钮 |
| `REJECT_LIMIT` | 驳回达 2 次，提示转争议 |
| 争议态 | 禁用验收接口转付，展示「人工裁定中」 |
| 成果 `result_pii_redacted=true` | 展示脱敏标记，正文为脱敏后内容 |

## 5. V4 我的任务

路由 `#/mine`。双 tab，按角色与状态分组展示用户相关任务与快捷操作。

### 5.1 功能点表

| 编号 | 功能点 | 说明 |
|---|---|---|
| V4-F01 | 双 tab | 「我发布的 / 我接的」切换，分别对应 `publisher_id` / `solver_id` 匹配当前用户 |
| V4-F02 | 状态分组 | 按进行中（`PENDING_REVIEW`/`PUBLISHED`/`DISPATCHING`/`ACCEPTED`/`IN_PROGRESS`/`SUBMITTED`/`DISPUTED`）与终态（`SETTLED`/`REJECTED`/`CANCELLED`/`EXPIRED`/`CLOSED`）分组 |
| V4-F03 | 任务摘要卡片 | 展示 `title / state / bounty / deadline / submit_count / reject_count` |
| V4-F04 | 快捷操作 | 验收、提交、争议、撤回、事件回放直接跳转 V3 |
| V4-F05 | 状态标签 | 双语状态标签与超时口径提示 |

### 5.2 交互流程

1. 进入 `#/mine` → `GET /api/tasks?include_terminal=true` 拉取全量 → 前端按 `publisher_id`/`solver_id` 分组。
2. 切换双 tab → 渲染对应分组；默认「我发布的」。
3. 点击任务/快捷操作 → 进入 V3 对应操作。

### 5.3 涉及的 API

| API | 用途 |
|---|---|
| `GET /api/tasks?include_terminal=true` | 含终态的任务全集，前端按归属过滤 |
| `GET /api/auth/me` | 当前用户 `user_id` 用于归属匹配 |

### 5.4 状态/错误分支

| 分支 | 处理 |
|---|---|
| 未登录 | 跳 V7 登录 |
| 空分组 | 展示「暂无发布/接取任务」空态 |
| demo 503 | 显示演示横幅，数据可能为空 |
| 终态任务 | 只读展示，不显示写操作 |

## 6. V5 SBC 账户

路由 `#/wallet`。展示余额、流水、锚定与非资产声明。

### 6.1 功能点表

| 编号 | 功能点 | 说明 |
|---|---|---|
| V5-F01 | 余额与信用分 | 展示 `userView.available_sbc / credit_score`（登录态） |
| V5-F02 | 流水列表字段 | `entries[]{seq,event_id,task_id,account,delta,rule_version,memo,created_at,prev_hash,hash}` |
| V5-F03 | balance_check | 展示 `balanced` 与五科目守恒说明 |
| V5-F04 | 锚定信息 | 展示 `anchor{anchor_id,merkle_root,leaf_count,pii_on_chain:false,task_body_on_chain:false}` |
| V5-F05 | 非资产声明 | 显著展示 SBC 不可兑付/不可转让/不可交易/无收益承诺（`/api/config.sbc_notice`） |

### 6.2 交互流程

1. 进入 `#/wallet` → `GET /api/ledger/:userId`（本人）→ 渲染余额、流水时间线、balance_check、锚定信息。
2. 流水按 `seq` 倒序；`memo` 展示科目说明；`hash/prev_hash` 可展开查看（哈希链）。
3. 顶部固定非资产声明横幅。

### 6.3 涉及的 API

| API | 用途 |
|---|---|

## 8. V7 登录 / 注册

路由 `#/auth`。角色选择、字段校验、邮箱验证提示。

### 8.1 功能点表

| 编号 | 功能点 | 说明 |
|---|---|---|
| V7-F01 | 登录/注册切换 | 两种模式 tab |
| V7-F02 | 角色选择 | 注册时选择 `publisher` / `solver`；admin 不经注册（bootstrap 引导） |
| V7-F03 | 注册字段 | `email / password(10–128) / display_name(1–64) / role / locale(可选)` |
| V7-F04 | 登录字段 | `email / password` |
| V7-F05 | 邮箱验证提示 | 注册后提示查收通知中的验证令牌，提供重新发送入口 |
| V7-F06 | GPC/DNT 提示 | 浏览器退出信号下个性化默认关闭，服务端强制中性排序 |
| V7-F07 | 登录后回跳 | 依据 `redirect` 参数回到原视图 |

### 8.2 交互流程

1. 注册 → 前端校验 → `POST /api/auth/register` → 成功保存 `session.csrf_token`、下发 Cookie → 提示邮箱验证 → 回跳。
2. 登录 → `POST /api/auth/login` → 成功保存 csrf_token → 回跳。
3. 邮箱验证 → 输入令牌 → `POST /api/auth/verify-email`；未收到 → `POST /api/auth/resend-verification`。
4. 退出 → `POST /api/auth/logout` → 清除会话 → 回 V1。

### 8.3 涉及的 API

| API | 用途 |
|---|---|
| `POST /api/auth/register` | 注册（含初始额度记账、验证令牌入队） |
| `POST /api/auth/login` | 登录（会话 + csrf_token） |
| `POST /api/auth/logout` | 退出 |
| `GET /api/auth/me` | 登录态判定 |
| `POST /api/auth/verify-email` / `POST /api/auth/resend-verification` | 邮箱验证 / 重发 |

### 8.4 状态/错误分支

| 分支 | 处理 |
|---|---|
| `EMAIL_TAKEN` 409 | 提示邮箱已注册，引导登录 |
| `INVALID_EMAIL` / `DISPOSABLE_EMAIL` / `INVALID_PASSWORD` / `INVALID_NAME` / `INVALID_ROLE` | 字段级提示 |
| `INVALID_CREDENTIALS` 401 | 统一提示「邮箱或密码错误」（不暴露账号是否存在） |
| `ACCOUNT_LOCKED` 423 | 提示临时锁定 15 分钟 |
| `verification_required=true` | 强制展示验证引导 |
| demo 503 | 注册/登录不可用，提示演示模式 |

## 10. V9 管理端（人工闸门）

管理端以**跳转 `/prod` 内部操作台**为主；用户端仅暴露状态进度，不承载 admin 操作表单。下表列出人工闸门清单与对应端点，供内嵌/跳转对照。

| 闸门 | 说明 | API | 前端承载 |
|---|---|---|---|
| 任务审核 | 通过冻结 / 驳回终态 | `POST /api/tasks/:id/review` | `/prod` 审核队列 |
| 触发推送 | dry-run 预览 + 分批触达 | `POST /api/tasks/:id/dispatch` | `/prod` 推送面板 |
| 超时自动验收 | 仅 admin 手动触发 `auto_accept` | `POST /api/tasks/:id/verify` | `/prod` |
| 争议裁定 | pay_solver/refund_publisher/close | `POST /api/tasks/:id/dispute action:resolve` | `/prod` 仲裁台 |
| 审核/争议/举报队列 | 汇总待办 | `GET /api/admin/queue` | `/prod` |
| 风控处置 | 风险标记 + 消解 | `GET /api/admin/risk`、`POST /api/admin/risk/resolve` | `/prod` |
| 备份 | 导出含个人数据，声明加密义务 | `GET /api/admin/backup` | `/prod` |
| 锚定 | 本地 Merkle 摘要，零 PII/正文 | `POST /api/admin/anchor` | `/prod` |
| 定时任务 | 只生成待人工确认工单 | `POST /api/admin/cron` | `/prod` |
| 运维观测 | 指标/审计/系统状态 | `GET /api/admin/{ops,metrics,audit}` | `/prod` |

> 所有 admin 端点 `requireRole(['admin'])` 且写 `audit_log`；模型 `model_decision:null`，不直判。用户版页脚提供「Operations console」入口跳转 `/prod.html`。
