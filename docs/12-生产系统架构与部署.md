## 1. 架构

```
浏览器 https://sambon.net/
   │  GET /                → _redirects 200 rewrite → /prod.html（生产操作台）
   │  GET /legal.html      → 隐私政策 / ToS / AUP / AI 透明度 / 举报
   │  GET /index.html      → L0 静态演示台（保留，页面内 mock，不发真实请求）
   │
   ├─ 静态资源（cloudflare/ 输出目录，Pages Git 集成自动上传）
   │
   └─ /api/*  → Cloudflare Pages Functions（仓库根 functions/，Git 集成自动编译）
                  functions/api/[[path]].js → prod/lib/api.js
                     ├─ prod/lib/domain.js  ← 由 src/domain.mjs 逐字节同步（状态机/权重/积分/脱敏唯一真源）
                     ├─ prod/lib/hash.js    ← 由 src/hash.mjs 逐字节同步（零依赖 SHA-256）
                     ├─ prod/lib/auth.js    PBKDF2 / 会话 / CSRF / RBAC / 限流
                     ├─ prod/lib/db.js      D1 prepare/bind/batch 薄适配
                     ├─ prod/lib/schema.js  表结构唯一真源（生成根目录 schema.sql）
                     ├─ prod/lib/response.js 统一响应 / 安全头
                     └─ D1（binding 名固定 DB）
                          users / sessions / tasks / ledger_entries / events /
                          idempotency / dispatches / consents / reports /
                          audit_log / rate_limits / meta
```

> **目录约束**：Cloudflare Pages 会把 `functions/` 下**每个** `.js/.ts` 文件都映射成一个路由，且每个路由文件必须导出 `onRequest*`。因此 `functions/` 下**只保留** `api/[[path]].js` 这一个路由文件，共享库统一放在仓库根的 `prod/lib/`。官方 *Module support* 文档给出的标准写法正是从路由文件相对 import 目录外的模块（`import { greeting } from "../src/greeting.ts"`），esbuild 会在构建时把被引用的模块一并打包；只要该模块被某个路由文件 import，就不会被当作独立路由。`tests/verify-production.mjs` 的 **P-73** 强制断言 `functions/` 下只有一个路由文件，防止后续误把工具文件放回该目录导致部署构建失败。
>
> **`_routes.json`**：官方 *Routing* 文档说明，一旦项目存在 `functions/` 目录，Pages 默认会把**所有**请求都交给 Function（静态请求也因此计费）。我们把 `_routes.json` 放在构建输出目录 `cloudflare/`，`include` 只为 `/api/*`，静态资源仍走静态通道；P-74 断言该配置存在且正确。

**为什么不是把 `src/server.mjs` 搬上云**：该文件用 `node:http` 起服务、进程级内存单例，Pages Functions 无 `createServer`、无跨请求内存。生产后端**重写编排与持久化**，但**复用 `src/domain.mjs` 的全部纯函数口径**（状态机、六项推送权重、榜单权重、冻结/结算公式、违禁词预检、PII 脱敏、LLM 规则兜底），并由 `tests/verify-production.mjs` 的 P-64/P-65 用 SHA-256 强制校验生成副本与源码逐字节一致 —— 不存在第二套业务口径。

## 3. 部署（推送即自动部署）

### 3.1 代码侧：一次 push 完成

`wangjia0910/sambon` 已连接 Cloudflare Pages Git 集成（Production branch = `main`，Output directory = `cloudflare`）。每次：

```bash
git push origin main
```

Cloudflare 会自动：① 编译仓库根 `functions/` 为 Pages Functions；② 上传 `cloudflare/` 静态产物；③ 生成新 Deployment。构建命令可留空，也可保留 `npm run build`（`package.json` 零依赖，`build` 会重新生成产物；两条路径产物一致）。

**产物清单（15 个文件）**：L0 八件套 + `prod.html`、`app.js`、`styles.css`、`legal.html`、`_redirects`、`_routes.json`、`demo.html`。`_redirects` 把 `/` 与 `/production` 重写到生产台，`/demo` 与 `/index.html` 保留 L0 演示台。

### 3.2 一次性动作：绑定 D1（**必须，且只能由你在控制台完成**）

> 本机无 `CLOUDFLARE_API_TOKEN` / Account ID，连接器里也没有 Cloudflare；公司网络对 `api.cloudflare.com` 直连返回 `000`。因此账号内的这一步无法代做，代码侧已做到「绑定即生效」。

| 步骤 | 位置 | 操作 | 完成标志 |
|---|---|---|---|
| 1 | Dashboard → **Storage & Databases → D1** | Create database，名称建议 `sambon-prod`，区域选主要用户所在区域 | 数据库创建成功 |
| 2 | Dashboard → **Workers & Pages → 项目 → Settings → Functions → D1 database bindings** | Add binding：Variable name 固定 **`DB`**，Database 选 `sambon-prod`；**Production 与 Preview 都要绑**（若预览环境也需可用） | 绑定列表出现 `DB` |
| 3 | 项目 → **Deployments → Retry deployment**（或再 push 一次） | 让新绑定生效 | `GET /api/health` 返回 `mode=production`、`db=d1` |

**无需执行迁移**：首次 API 请求自动跑 `prod/lib/schema.js` 的 `CREATE TABLE IF NOT EXISTS`，并在 `meta` 表写入 `sambon-prod-schema-v1.0`。根目录 `schema.sql` 只是同一真源的导出，供显式执行：

```bash
npx wrangler d1 execute sambon-prod --file=schema.sql --remote
```

### 3.3 环境变量（Settings → Environment variables，Production）

| 变量 | 是否必填 | 说明 |
|---|---|---|
| `ADMIN_BOOTSTRAP_TOKEN` | **首次需要** | 首名管理员引导令牌。创建完 admin 后建议移除该变量，端点随即返回 503 |
| `INITIAL_SBC` | 可选 | 新账号平台内贡献积分初始额度，默认 `1000`；非资产、不可兑付 |
| `PBKDF2_ITERATIONS` | 可选 | 默认 `120000`，**不建议下调**；本地回归才设 `2000` |
| `COOKIE_SECURE` | 不要设 | 生产强制 `Secure`；仅本地 http 联调设 `false` |
| `RATE_LIMIT_DISABLED` | 不要设 | 生产强制启用限流；仅本地回归设 `true` |

**首次创建管理员**（引导端点只需用一次）：

```bash
curl -X POST https://sambon.net/api/admin/bootstrap \
  -H 'Content-Type: application/json' \
  -d '{"bootstrap_token":"<ADMIN_BOOTSTRAP_TOKEN>","email":"<你的管理员邮箱>","password":"<≥12位强口令>","display_name":"平台管理员"}'
```

随后用该账号在页面登录；publisher / solver 由页面自行注册。系统**不含任何内置默认账号或口令**。

### 3.4 部署后核验（按顺序）

1. `GET https://sambon.net/api/health` → `{"ok":true,"data":{"mode":"production","db":"d1",...}}`
2. `GET https://sambon.net/api/config` → `weight_version=v1.0`、`algorithm_degraded=true`、`account_level_preference=true`
3. 打开 `https://sambon.net/` → **生产系统操作台**（标题含「生产系统操作台」），无橙色演示横幅
4. `https://sambon.net/legal.html` → 隐私政策 / ToS / AUP / AI 透明度 / 举报通道可访问
5. `https://sambon.net/index.html` → L0 演示台仍可打开（浏览器内 mock，不与生产后端互相干扰）
6. 浏览器控制台执行红线检查：`fetch('/api/sbc/transfer',{method:'POST',body:'{}'}).then(r=>r.status)` → `404`
7. 注册 publisher + solver → 走一遍 发布 → 管理员审核 → 推送 → 接单 → 提交（填手机号验证脱敏）→ 验收 → 结算
8. `GET /api/ledger/<user_id>` → `balance_check.balanced=true`、`anchor.pii_on_chain=false`

> 若第 1 步仍是 `mode=demo`，说明 D1 绑定未生效（常见原因：只绑了 Production 没绑 Preview、绑定后未重新部署、变量名不是 `DB`）。此时站点会显示演示横幅并禁用写操作，**不会静默写入内存**。

### 3.5 回滚

- Pages → Deployments → 对上一个成功版本 **Rollback**，即时生效；本地对应 `git revert` 后 push。
- D1 数据不会随代码回滚自动还原；如需数据回滚须从 D1 导出 / Time Travel 恢复（请先配置备份策略，属于 L2 待办）。
- `_redirects` 中删掉 `/` 规则即可把主入口退回 L0 演示台。

## 5. 安全与合规设计（对应 `docs/11` V2-O）

| 跨境传输 | Cloudflare DPA + SCC / TIA（EU-US DPF 仍有效但须备回退）—— **仍需法务书面核销，代码不能替代** |

| 会话安全 | PBKDF2-SHA256 120000 轮 + 16 字节盐；token 仅以 SHA-256 入库；httpOnly + Secure + SameSite=Lax；CSRF 双提交 + Origin 校验；24h 过期 |

## 7. 明确边界（不得对外越界表述）

1. 本轮交付的是**适用于 Cloudflare 部署的生产系统代码与自动部署链路**，不是「平台已正式上线 / 已开放注册」。对外仍应表述为「生产系统演示环境 / 在线预览」。
2. `docs/07` 仍 **0/29**，V1–V8 仍「未上线、不触发」，法务结论仍为「有条件通过、未触发一票否决」，G6 未通过、L1/L2 **No-Go**。
3. 解除境内备案闸门（D-12）**不等于零合规**：V2-O 六组、PIPL 第 3 条适用性（若运营 / 开发 / 数据处理实际发生在境内）、目标市场执业律师书面复核仍须完成。
4. 不得宣称「已接真实支付 / 大模型 / 公链 / 消息通道」；LLM 适配层仍是规则化兜底（`degraded=true`）。
5. 账本哈希链是**本地可审计摘要**，未接任何公链；零 PII、零任务正文。
6. D1 为单库写入；跨区域强一致、并发抢单的严格串行化需 Durable Objects（L2 待办）。当前幂等依赖 `event_id` 唯一键 + `db.batch()` 事务，已在回归中验证重复 `event_id` 不重复落库。
