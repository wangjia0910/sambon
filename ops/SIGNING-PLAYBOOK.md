> 本包用法：按四类分组逐项推进，每完成一项在 `ops/readiness.json` 填

## 0. 四类签署动作总览

| 类别 | 含义 | 项数 | 谁能推进 |
|---|---|---|---|
| **A · 自签/自证** | 由你（运营方）操作控制台或填记录即可留痕 | 5（E-03/04/05/14/17） | 你本人 |
| **B · 律师签署** | 必须由目标市场执业律师出具书面意见 | 7（E-06~E-12） | 律师（可用律师智能体起草+你找执业律师签） |
| **C · 第三方出具** | 需外部机构/服务商报告或合同 | 4（E-13/15/16/19） | 服务商 / 第三方测试机构 |
| **D · 运营落地** | 汇总与外部签字，需真实跑起来并留痕 | 2（E-18/20） | 你 + 全体 |

> 合计 5+7+4+2 = **18 项**，与 `ops/readiness.json` 未核销项一一对应。

> 关键区分：**B/C 类不能"自己填 verified=true"**——门禁只查字段完整，但法务真实性由 E-20 签字人背书，伪造会构成虚假陈述。

## A · 自签 / 自证（5 项，你可立即闭环）

### E-03 生产环境变量与密钥已配置、密钥已轮换
- **基线**：`ops/config-audit.md` 已记录线上 health 快照 + 轮换清单；PAT 按你 2026-11-13 指令保留、不撤销。
- **要做什么**：在 Cloudflare Pages → Settings → Environment variables 核对 `ADMIN_BOOTSTRAP_TOKEN`（引导后用后移除）、`CRON_SECRET`、`LLM_API_KEY`、`NOTIFY_WEBHOOK_SECRET`；按需轮换。
- **签哪**：无外部签字，你自己留痕即可。
- **evidence 模板**：填入 `ops/config-audit.md` §4 的要点 + 操作日期。
- **注意**：PAT 撤销一项按你的指令标"不适用（保留，仅仓库推送最小权限）"，写明即可。

### E-04 外部定时任务调度器已上线
- **模板**：`ops/cron/github-action.yml`（GitHub Actions 方案）或 `ops/cron/worker.js`（Cloudflare Worker Cron 备选）。
- **要做什么**：二选一部署，确认对 `/api/admin/cron` 定时调用，连续 7 天执行日志。
- **签哪**：自证；贴调度器配置截图 + 7 天日志片段（可打码）。
- **evidence 模板**：`已部署 GitHub Actions/Worker Cron，cron 表达式 X，2026-MM-DD 至 MM-DD 连续 7 天 200 响应 N 次，日志见 <内部路径>`。

### E-05 备份、留存与 Time Travel 演练
- **模板**：`ops/backup-runbook.md`。
- **要做什么**：确认 D1 备份策略，做一次真实恢复演练（在演练库，勿动生产），记录恢复后校验结果。
- **签哪**：自证（运维负责人）。
- **evidence 模板**：`演练日期/操作人/恢复点/核对结论` 填入 `ops/readiness.json`。

### E-14 WAF / 风控名单与滥用处置流程
- **模板**：`ops/waf-rules.md`（规则建议 + 风控名单 + 滥用 SLA）。
- **要做什么**：在 Cloudflare 控制台实际配置 WAF/速率限制，跑一个滥用处置样例。
- **签哪**：自证 + 安全负责人。
- **evidence 模板**：`WAF 规则 ID / 速率阈值 / 处置样例单号 / SLA 时效`。

### E-17 人工闸门演练与值班安排
- **要做什么**：对审核/推送/验收/争议裁定/风控处置逐项做一次人工确认演练，出值班表。
- **签哪**：自证（产品 + 运营负责人）。
- **evidence 模板**：`演练项清单 + 每项确认人 + 值班表链接 + 日期`。
- **备注**：这条与代码侧 C-08 人工闸门呼应，是"流程确实有人按"的证据。

## B · 律师签署（6 项，需执业律师出具）

> **重要边界**：律师智能体可帮你起草/审阅/列清单，但**书面意见必须由目标市场执业律师签署并署名**才能核销。AI 生成物不能替代律师签字。

### E-06 V2-O 六组全部核销
- **内容**：地域与协议、隐私与 Cookie、跨境传输、自动化决策、SBC 非资产与税务、未成年人与内容治理——六组逐项书面结论。
- **材料**：`ops/compliance-evidence-pack.md` §一（docs/07 的 29 项跟踪表）。
- **签发**：律师在六组结论上签字 + 日期。

### E-07 目标市场执业律师书面复核意见
- **索要文件**：覆盖 GDPR/UK GDPR、ePrivacy、CCPA/CPRA、COPPA、DSA Art.27、EU AI Act Art.50、GDPR Art.22 的书面意见。
- **发给谁**：目标市场（海外）执业律师。
- **签发**：律师署名 + 执业号 + 日期。

### E-08 Cloudflare DPA + SCC / TIA 已签署
- **内容**：DPA 版本、SCC(2021/914) 签署件、传输影响评估 TIA、EU-US DPF 回退方案。
- **注意**：DPF 不可作唯一依据，须 SCC 回退（与 O-3 同源）。
- **签发**：Cloudflare 侧 DPA 在线接受 + 法务对 SCC/TIA 签字。

### E-09 隐私政策 / ToS / AUP 法务定稿
- **草稿**：`ops/legal-drafts.md`（双语，摘要稿待补正式条款）。
- **要做什么**：补全为正式稿 → 律师审定 → 标注版本号、发布日期、同意留痕方案 → 上线到 `legal.html`。
- **签发**：律师定稿签字；evidence 贴上线版 URL + 版本号。

### E-10 PIPL 第 3 条适用性评估
- **背景**：当前部署面向海外、服务在 Cloudflare，需书面判定运营/开发/客服/数据处理实际发生地。
- **签发**：律师书面结论；若判定涉境内，再补数据出境合规结论（这会改变合规基线，需复评 docs/11 §1.3）。
- **提醒**：这条结论直接决定项目是否触发境内备案，**优先级高**。

### E-11 未成年人年龄核验（V8）
- **内容**：真实年龄核验方案 + 供应商评估；或明确限定 18+ 且可执行的技术与流程证据。
- **当前基线**：`prod/site/legal.html` 已声明 18+ 限制与未成年人条款；前端无年龄门槛交互。
- **要做什么**：二选一——(a) 接入年龄核验供应商并出评估；(b) 维持 18+ 限定，但补"技术上如何拒绝未成年人注册/举报入口"的可执行证据（拦截用例须 100%）。
- **签发**：律师对方案合规性的书面确认 + 产品/风控对拦截用例的验收签字。
- **evidence**：方案文档 + 拦截用例清单 + 律师确认页。

### E-12 SBC 非资产与支付税务书面结论
- **内容**：SBC 不构成加密资产/支付工具/收益承诺的法律意见；DAC7 / 1099-K / VAT 适用性。
- **签发**：法务 + 财务 + 律师联合署名。
- **红线**：与 §10 一致——SBC 不接真实法币支付，结论须明确这一点。

## C · 第三方出具（4 项，需外部机构/服务商）

### E-13 真实通知 / 邮件通道已接通
- **要做什么**：`NOTIFY_WEBHOOK_URL` 指向真实邮件/推送服务商（如 Resend/Postmark），签合同，验证送达率。
- **注意**：`queue_only` 降级不算核销——必须真实发出过邮件。
- **evidence**：服务商合同 + 送达率记录 + 一封真实通知截图（打码 PII）。

### E-15 安全事件响应与 DPO / 代表指定
- **要做什么**：事件响应预案 + 72 小时通报流程 + 指定 DPO 或欧盟代表（DSA Art.27）+ 联系方式可用性验证。
- **签发**：指定文件（你签字）+ 代表接受函（第三方签字）。
- **evidence**：预案文档 + 代表委任书 + 联系方式验证记录。

### E-16 渗透测试 / 压测 / 灾备演练
- **要做什么**：第三方或内部渗透测试报告（无高危）；压测结论（闭环≥99.5% / ≥500TPS / P95≤200ms）；灾备切换演练记录。
- **对应**：docs/07 的 V4/V5/V6。
- **evidence**：三份报告/记录，均需出具方署名。

### E-19 L1 灰度结果复核
- **要做什么**：单一海外区域灰度数据 + 回滚触发线监测记录 + 无重大事故说明。
- **前置**：E-18 完成后才能灰度。
- **evidence**：灰度报告 + Go/No-Go 记录（可自证，但建议第三方或签字人复核）。

## 1. 推荐推进顺序（关键路径）

```
第一步（解锁合规基线）：E-10 PIPL 适用性  →  决定是否触发境内复评
        ↓
第二步（法律文件定稿）：E-09 法务文稿 → 律师审定
        ↓
第三步（律师集中签署）：E-06 / E-07 / E-08 / E-12（可一次性打包发给律师）
        ↓
第四步（第三方并行）：E-13 邮件 / E-15 DPO / E-16 测试报告
        ↓
第五步（自签补证）：E-03 / E-04 / E-05 / E-14 / E-17
        ↓
收口：E-18 汇总 → E-19 灰度 → E-20 有权人 Go
```

**最快闭环建议**：先做 A 类 5 项（你可立即自证，约 1-2 天），同时把 B 类 6 项打包发给律师。E-10 单独优先，因为它可能改变整个合规基线。

## 2. 签署留痕统一格式

每项在 `ops/readiness.json` 的 evidence 字段用统一句式：

```
<动作>；<主体/签署人>；<日期 YYYY-MM-DD>；<证据存放位置或URL>
```

例：
```
隐私政策 ToS AUP 法务定稿 v1.0；张三律师（执业号 XXXX）；2026-11-25；
https://sambon.net/legal.html + ops/signed/legal-v1.0.pdf
```
